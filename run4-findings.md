# Разбор прогона 4

Патч `fix-run4-formula-and-plan.patch` применяется поверх всех предыдущих изменений, включая `fix-ocr-single-request.patch`. Тесты и desc.yaml в патч не включены.

## Подтверждённые причины и исправления

1. **Расчёт формул не загружается.** В тексте прогона: `cannot import name '_BUILTIN_REGISTRY_DIR'`. Цепочка: calc.formula → ratios.compute_ratios → extract_result → versioning. Старый импорт остался после перехода реестра на registry_layers. В versioning оставлен только путь-маркер совместимости, не требующий существования старого каталога. Действующие правила по-прежнему компилируются из слоёв. Тест проверяет загрузку, отпечаток реестра и фактический расчёт A/B.

2. **Первый план отвергнут из-за текста перед JSON.** Планировщик был запущен: задачи e8c20559 и затем 47642d5a. Приёмщик раньше понимал чистый JSON и Markdown-блок, но не пояснение перед обычным объектом. Теперь извлекается один полный объект; Pydantic по-прежнему проверяет полную схему плана. Несколько объектов отвергаются, битый JSON не исправляется извлечением вложенных фрагментов.

3. **Противоречивое описание средств банков.** INTERBANK_LOANS имеет название «Средства банков» и синонимы Due to banks / Interbank borrowings, но описание говорило о выданных кредитах. Описание и подсказка приведены к обязательствам. INTERBANK_DEPOSITS по существующему реестру означает актив «Средства в банках». Идентификаторы и формулы не переименованы.

## Состояние интеграций

- OCR успешен: 70 страниц, 66 таблиц, 298187 символов; HTTP upload/extract/download вернули 200.
- В GigaAgent есть временные ошибки PostgreSQL около 00:54 UTC и переподключения Dialogs. После них прогон продолжился; это не причина ImportError в AIFA. Для повторяющихся сбоев нужны журналы БД/прокси за те же интервалы.
- LLM иногда возвращал неполный ответ; клиент повторял запросы. Последующий ответ получен.
- Лимит процессов при экспорте Excel упоминается агентом, но системного вывода команды и значений лимитов в приложенных логах нет. Причина не установлена; лимиты контейнеров патч не меняет.
- AIFA предупреждает о незаданных FINENGINE_EXPECTED_POLICY_HASH и внутренней авторизации. Это отдельные настройки развёртывания, не причина падения формул.

## Качество итоговых чисел

Ответ агента нельзя считать проверенной выгрузкой: он сам сообщил о выдуманных ID и недочитанных значениях. В таблице перепутаны подписи межбанковских активов/обязательств, а нематериальные активы приведены с подозрительным масштабом. Исправление описания реестра устраняет один источник путаницы, но не доказывает корректность уже выданных чисел. Для проверки масштаба нужны исходные ExtractedMetric с value/unit/page и их источниками: в этих логах они не записаны. После исправлений нужен новый прогон с проверкой артефактов и единиц.
