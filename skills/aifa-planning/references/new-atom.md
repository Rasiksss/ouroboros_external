# Новый атом — только если без него нельзя

Порядок строгий:
1. часть задачи — стандартный процесс AIFA → сценарий;
2. есть подходящий атом в каталоге (`references/atoms.md`) — используй его;
3. задача решается комбинацией атомов каталога — комбинируй;
4. подходит уже созданный `eph.*` (раздел «Созданные атомы» в `aifa_state`) — используй его;
5. только иначе — опиши новый атом в `new_atoms` хода `aifa_move`.

Объявление атома в `new_atoms` его не запускает и ничего не скачивает: атом только создаётся.
Данные появятся, лишь когда этот атом вызван шагом в `steps` — в том же ходе; каждый атом из
`new_atoms` укажи в `steps` этого же хода (атом без шага служба запустит сама отдельным шагом). В
разделе «Созданные атомы» рядом с атомом стоит «НЕ ЗАПУЩЕН», пока нет артефакта его типа: данных ещё
нет, не считай их полученными.

Новые атомы бывают двух видов. `requires` и `output_schema` — массив и объект, не строки: не
заключай `[...]` и `{...}` в кавычки.

## Атом с кодом

Считает что-то из входов. Ты не пишешь код — ты описываешь контракт, код напишет автор атомов службы:
- `name` — `eph.<snake_case>`;
- `purpose` — что делает атом, 1–3 предложения (до 600 знаков), с деталями: формула, как выровнять
  периоды, в каких единицах результат, как разобрать скачанный файл;
- `requires` — входы `{"input_type", "concept"}`: типы из каталога или `dyn:*` созданных атомов;
- `output_type` — `dyn:<snake_case>`;
- `output_schema` — JSON Schema результата-объекта; у КАЖДОГО числового поля `x-unit`
  («RUB mln», «USD/bbl», «%», «dimensionless»).

Код исполняется в изолированной комнате без сети.

**Пиши атом с кодом, когда его входы уже в артефактах.** Если вход (показатель отчёта, результат
сценария, скачанный файл) появится только в этом ходе, служба не станет писать код: она ответит
«входов ещё нет» (`ОТКАЗ нет_входов`). Сначала получи входы (сценарием или шагами), атом опиши
следующим ходом.

Чтобы исправить атом, пришли его описание с тем же `name`: автор получит прошлый код и ошибку.

## Файл как результат

Файл (Excel, презентацию, документ) создаёт атом с кодом: автор запишет его в каталог `out/`,
служба сохранит его как артефакт `FileArtifact` — в таблице артефактов это строка с id, именем и
структурой (листы и число формул, слайды, абзацы). Формат определяет код атома; в комнате есть
openpyxl, pandas, python-pptx, python-docx.
- В `purpose` опиши структуру файла (листы, столбцы, формулы, слайды) и из каких входов берутся данные;
  `output_schema` может быть `{"type": "object"}`.
- Атом каталога `out.file` выгружает форму или отчёт как есть: один лист, только значения, без
  формул. Если пользователь задал структуру файла (несколько листов, формулы в ячейках, свои
  столбцы, слайды), `out.file` не подходит — сразу описывай атом с кодом.
- Входы такого атома — уже полученные показатели: `{"input_type": "ExtractedMetric", "concept": "*"}`
  и `{"input_type": "CalculatedMetric", "concept": "*"}` дают все показатели этих типов.
- Один файл — один атом: не дроби сборку файла на несколько атомов.

## Атом-загрузка

Скачивает одну публичную страницу или файл данных (CSV, JSON, текст):
- `name`, `output_type` — как выше;
- `url` — точный адрес из находок `web.search`;
- `purpose` — что там: о чём страница, столбцы, единицы, частота.

Кода у него нет. Результат — объект с полями `url`, `content_type`, `text`; у страницы `text` — её
текст без разметки, длинный обрезан. Разбирать `text` будет атом с кодом, которому этот `dyn:*` нужен
на входе. Каждая страница — отдельный атом: скачивай только то, без чего не ответить.

## Когда служба отклонит атом

- у атома-загрузки есть `requires` — соединять скачанное с данными отчёта должен атом с кодом
  (`ОТКАЗ неверные_аргументы`);
- у атома с кодом нет `requires` — ему не из чего считать;
- атом производит что-то кроме `dyn:*` (`ОТКАЗ не_dyn_тип`): числа из отчёта получают только атомы
  каталога;
- у числового поля схемы нет `x-unit` (`ОТКАЗ нет_единицы`);
- исчерпан предел новых атомов (`ОТКАЗ лимит_атомов`).
