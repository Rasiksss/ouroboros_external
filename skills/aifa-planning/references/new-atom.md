# Новый атом — только если без него нельзя

Порядок строгий:
1. часть задачи — сценарий службы (`references/scenarios.md`) → часть цели в `goals`;
2. есть подходящий атом в каталоге — его карточка в `aifa_atoms(action="list")`: входы, выходы, форматы и
   ограничения покрывают нужное — используй его (`references/atoms.md` — лишь снимок каталога);
3. задача решается комбинацией атомов каталога — комбинируй;
4. подходит уже созданный `eph.*` (в `aifa_atoms` область «временный, этот Case») — используй его, а его код
   смотри через `get`;
5. только иначе — заведи атом: с кодом — заданием подзадаче автора (`SKILL.md`, «Делегирование»), загрузку
   страницы — в `new_atoms` хода `aifa_move`.

Пробел назови по карточкам: чего именно не умеет атом каталога. Структура файла (листы, формулы, слайды,
документ), которую карточка покрывает, — пункт 2; не покрывает — пункт 5. Атом каталога подходит, но его
входы ещё не получены, — сначала получи данные: это не причина создавать новый атом.

Атом с кодом в `new_atoms` служба отклонит (`ОТКАЗ неверные_аргументы`): код пишет только подзадача.
Объявление атома-загрузки в `new_atoms` его не запускает и ничего не скачивает: атом только создаётся.
Данные появятся, лишь когда этот атом вызван шагом в `steps` — в том же ходе; каждый атом из
`new_atoms` укажи в `steps` этого же хода (атом без шага служба запустит сама отдельным шагом). В
разделе «Созданные атомы» рядом с атомом стоит «НЕ ЗАПУЩЕН», пока нет артефакта его типа: данных ещё
нет, не считай их полученными.

Новые атомы бывают двух видов. `requires` и `output_schema` — массив и объект, не строки: не
заключай `[...]` и `{...}` в кавычки.

## Атом с кодом

Считает что-то из входов. Ты не пишешь код: описываешь контракт в задании подзадаче автора, код пишет она, и
служба принимает его, когда он прошёл проверку (`SKILL.md`, «Делегирование»). Что назвать в задании:
- `name` — `eph.<snake_case>`;
- `purpose` — что делает атом, 1–3 предложения (до 600 знаков), с деталями: формула, как выровнять
  периоды, в каких единицах результат, как разобрать скачанный файл;
- `requires` — входы `{"input_type", "concept"}`: типы из каталога или `dyn:*` созданных атомов; `concept` —
  код показателя (`EBITDA`) только у показателей; у форм, отчётов и `dyn:*` концепта нет — не указывай его;
- `output_type` — `dyn:<snake_case>`;
- `output_schema` — JSON Schema результата-объекта; у КАЖДОГО числового поля `x-unit`
  («RUB mln», «USD/bbl», «%», «dimensionless»).

Код исполняется в изолированной комнате без сети. Принятая сдача — уже исполнение атома: его результат и
файлы ложатся в таблицу артефактов, шагом его запускать не нужно.

**Поручай атом с кодом, когда его входы уже в артефактах.** Если вход (показатель отчёта, результат
сценария, скачанный файл) появится только в этом ходе, служба не примет код: подзадача получит отказ
«входов ещё нет» (`нет_входов`) и вернётся ни с чем. Сначала получи входы (частью цели или шагами), потом
поручай атом; id нужных артефактов назови в задании.

Чтобы исправить атом, поручи его заново с тем же `name` (`SKILL.md`, «Делегирование»).

## Файл как результат

Файл (Excel, презентацию, документ) создаёт атом с кодом: подзадача запишет его в каталог `out/`,
служба сохранит его как артефакт `FileArtifact` — в таблице артефактов это строка с id, именем и
структурой (листы и число формул, слайды, абзацы). Формат определяет код атома; в комнате есть
openpyxl, pandas, python-pptx, python-docx.
- В `purpose` опиши структуру файла (листы, столбцы, формулы, слайды) и из каких входов берутся данные;
  `output_schema` может быть `{"type": "object"}`.
- Что выгружает `out.file` и в каких форматах, написано в его карточке (`aifa_atoms`): источник,
  параметры, ограничения. Структуру, которой нет в карточках, собирает атом с кодом; пробел назови в задании.
- Входы такого атома — уже полученные показатели: `{"input_type": "ExtractedMetric"}` и
  `{"input_type": "CalculatedMetric"}` без `concept` дают все показатели этих типов; форма роли —
  `{"input_type": "FormOutput"}`, отчёт с выводами — `{"input_type": "ReportOutput"}`.
- Один файл — один атом: не дроби сборку файла на несколько атомов.
- Файл пользователю отдаёт служба — из `out/` принятого атома; сведения о листах и формулах проверяет
  корень по критериям плана. Собрать файл самому в песочнице и отправить (`code_exec`, затем `file_read`) — запасной путь,
  когда атома нет и не будет: служба приложит и такой файл, но без проверки. Цикл исчерпан, а файла нет —
  так и скажи: что готово, чего нет и почему.

## Атом-загрузка

Скачивает одну публичную страницу или файл данных (CSV, JSON, текст):
- `name`, `output_type` — как выше;
- `url` — точный адрес из находок `web.search`;
- `purpose` — что там: о чём страница, столбцы, единицы, частота.

Кода у него нет. Результат — объект с полями `url`, `content_type`, `text`; у страницы `text` — её
текст без разметки, длинный обрезан. Разбирать `text` будет атом с кодом, которому этот `dyn:*` нужен
на входе. Каждая страница — отдельный атом: скачивай только то, без чего не ответить.

## Когда служба отклонит атом

Те же правила служба применяет к коду, который сдаёт подзадача, поэтому описывай атом в задании так, чтобы они
выполнялись.

- атом с кодом в `new_atoms` (`ОТКАЗ неверные_аргументы`: «подзадача и `aifa_register_atom`») — код заводит
  только подзадача автора;
- у атома-загрузки есть `requires` — соединять скачанное с данными отчёта должен атом с кодом
  (`ОТКАЗ неверные_аргументы`);
- у атома с кодом нет `requires` — ему не из чего считать;
- атом производит что-то кроме `dyn:*` (`ОТКАЗ не_dyn_тип`): числа из отчёта получают только атомы
  каталога;
- у числового поля схемы нет `x-unit` (`ОТКАЗ нет_единицы`);
- исчерпан предел новых атомов (`ОТКАЗ лимит_атомов`).
