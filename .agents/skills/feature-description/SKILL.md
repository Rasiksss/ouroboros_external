# Feature Description From Git Branch

Создай бизнес-описание изменений текущей Git-ветки.

## Запуск

Базовая ветка — необязательный параметр:

```text
$feature-description
$feature-description main
$feature-description release/1.2
```

Без параметра используй `develop`. Не переключай ветки. Текущая ветка — анализируемая, переданная ветка — база сравнения.

Если указанная ветка отсутствует локально, попробуй `origin/<имя-ветки>`. Если базу определить нельзя, сообщи об этом кратко и не подменяй её другой веткой.

## Сбор информации

Определи merge base и компактно изучи:

- commits и список изменённых файлов относительно базы; извлеки идентификаторы задач вида `GGGNT-<номер>` из заголовков commits;
- только релевантные фрагменты production-кода;
- изменённые и ближайшие тесты;
- публичные API, CLI, UI, сообщения и конфигурацию.

Учитывай committed, staged и tracked uncommitted изменения. Отдельно предупреди о существенных untracked-файлах. Не читай целиком большие, generated-файлы, зависимости и логи.

## Правила вывода

- Ничего не записывай и не изменяй в репозитории.
- Не задавай разработчику вопросов.
- Описывай пользовательский результат, а не внутреннюю реализацию.
- Не придумывай лимиты, гарантии и бизнес-ценность.
- Подтверждённые факты формулируй утвердительно; выводы из кода помечай как предположения.
- Если данных нет, пиши: «Не удалось определить по изменениям ветки».
- Если ветка содержит независимые фичи, сформируй отдельную карточку для каждой.
- Если для карточки однозначно найден идентификатор задачи, добавь его в заголовок и используй понятную часть заголовка связанного commit: `# GGGNT-1577. Добавить в промп защиту на отправку в поиск сберовских идентификаторов`.
- Если одна карточка связана с несколькими разными `GGGNT-<номер>`, раздели её по задачам, когда изменения независимы. Иначе укажи все номера в разделе «Что изменилось», но не выбирай один произвольно для заголовка.
- Не восстанавливай номер задачи из имени ветки, файлов или текста кода: используй только явный идентификатор из заголовка commit.
- Выведи только готовые карточки и короткий список сведений, требующих подтверждения.

## Формат карточки

# GGGNT-<номер>. <Название фичи>

Если идентификатор задачи не найден или неоднозначен:

# <Название фичи>

## 1. Бизнес-задача и ценность

Опиши проблему и пользовательский результат. Отделяй подтверждённые сведения от предположений.

## 2. Как пользоваться

Дай пошаговый пользовательский сценарий. Если функция действует автоматически, явно напиши это.

## 3. Что изменилось

Было: ...

Стало: ...

Старый способ: продолжает работать / удалён / не удалось определить по изменениям ветки.

## 4. Границы и ограничения

Перечисли подтверждённые условия, лимиты, права, таймауты, флаги конфигурации и внешние зависимости.

## 5. Как проверить, что работает

Составь воспроизводимый сценарий на основе поведения и тестов. Для скрытого свойства отдельно укажи системный критерий проверки.

## Примеры

Для ориентира по уровню конкретики и формулировкам прочитай [успешные примеры](references/successful-examples.md). Не переноси из них факты, ограничения или названия в описание другой ветки.
