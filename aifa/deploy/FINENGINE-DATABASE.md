# База finengine: подробное описание всех таблиц

Дополнение к пункту 3.1 инфраструктурной инструкции. Сверено 03.11.2026 со статическими SQLAlchemy-моделями текущего репозитория. БД не изменялась; SQL и тесты не выполнялись.

SQL для первичного создания: [finengine-schema.sql](finengine-schema.sql).
Скрипт сверён с моделями 05.11.2026. Целевая база — `aif_aef_metadb_dev`, схема —
`aif-aef-agnbf-af-aifaouroboros-finengine-db`. Он проверяет имя подключённой базы,
создаёт схему при отсутствии и размещает в ней таблицы и индексы.
Имя схемы в SQL заключено в двойные кавычки из-за дефисов.

В `store/engine.py` разрешены латинские буквы, цифры, подчёркивания и дефисы
(до 63 символов, первый символ — буква или подчёркивание). Имя передаётся
драйверу PostgreSQL в двойных кавычках. Для выбранной схемы задайте
`FINENGINE_PG_SCHEMA=aif-aef-agnbf-af-aifaouroboros-finengine-db`.

## Что заказать DBA

Выделить базу `finengine` либо отдельную схему в существующей корпоративной PostgreSQL, роль приложения и установочную роль по правилам контура. Все 22 таблицы размещаются совместно; девять настроек подключения могут указывать на одну базу. Схема AIFA задаётся `FINENGINE_PG_SCHEMA`; её нужно создать заранее. Не смешивать эти таблицы с таблицами ядра Ouroboros или Workstation.

Создать структуру по моделям текущей версии с PK, индексами, UNIQUE и объявленными FK. Не добавлять предполагаемые FK и каскадные удаления: большинство связей здесь логические. Рабочей роли нужны права на операции приложения и последовательности; установочные DDL-права согласуются отдельно. Учесть, что приложение вызывает create_all и содержит отдельные проверки/обновления структуры.

## Как читать состав

- «NULL: нет» означает NOT NULL; PK также не допускает NULL.
- JSON и JSONB указаны именно для PostgreSQL. Вложенные поля не становятся SQL-колонками и не получают индексов автоматически.
- «По умолчанию» — `default=` в SQLAlchemy, а не гарантированный серверный DEFAULT. При ручном INSERT вне приложения значения могут потребоваться явно.
- «—» означает отсутствие объявленного `default=`, а не обязательное отсутствие генерации ID. Генерация целочисленных ID описана отдельно.
- Временные поля double precision/bigint не следует без миграции превращать в timestamptz: сохраняется формат приложения.
- Во всех таблицах есть индекс PK; ниже перечислены дополнительные индексы и ограничения.
- Это описание схемы, не готовый DDL-скрипт. create_all не выполняет универсальное обновление существующих таблиц.

## 1. `users`

Учётные записи пользователей AIFA. ID используется службой как идентификатор владельца при обращении к ядру.

Подключение: `FINENGINE_AUTH_DATABASE_URL`.

Источник: [auth/db.py](../finengine/src/finengine/auth/db.py).

| Поле | PostgreSQL-тип | NULL | По умолчанию в приложении | Назначение |
|---|---|---|---|---|
| `id` | `integer` | нет | — | Идентификатор записи |
| `username` | `varchar(64)` | нет | — | Логин пользователя |
| `password_hash` | `varchar(255)` | нет | — | Хеш пароля; исходный пароль здесь не хранится |
| `is_admin` | `boolean` | нет | False | Признак администратора |
| `created_at` | `timestamptz` | нет | Текущее UTC-время, вычисляет приложение | Время создания |

## Подготовка и эксплуатация

1. Получить host/port/database/schema, credentials, TLS/CA, лимиты соединений и правила резервного копирования.
2. Создать схему, если она используется. Команда `python -m finengine.store.ensure_schema --apply` создаёт схему, не все таблицы.
3. Подготовить все 22 таблицы текущей версии согласованным установочным шагом. `python -m finengine.store.migrate_cases` относится только к семи таблицам кейсов.
4. Согласовать запуск с ограниченной рабочей ролью: приложение использует create_all и отдельные изменения структуры, одной выдачи DML-прав без проверки недостаточно.
5. Для существующей базы сначала сравнить реальную структуру с моделями; create_all не добавит все отсутствующие колонки и ограничения автоматически.
6. Учесть рост journal, station_run, JSON-результатов, истории профилей и новостей. Сроки хранения/очистку согласовать с приложением; произвольное удаление по времени может нарушить историю и связи.
7. Резервировать БД совместно с файлами S3: восстановленные SQL-ссылки должны указывать на существующие объекты. SQL-бэкап не содержит оригиналы документов.
8. Multiuser не требует таблиц на каждого пользователя: владельцы разделяются owner_id/user_id/owner_key и проверками доступа приложения. Наличие этих колонок само по себе не является PostgreSQL RLS.

Таблицы новостей и сценариев входят в структуру текущего приложения, даже если их внешние источники пока не используются. В текущих определениях нет обязательного pgvector или внешней векторной БД. Это не исключает потребность расширений у отдельно взятого ядра Ouroboros.
