## Когда

Любой обычный запрос по уже загруженной финансовой отчётности: один
зарегистрированный или ad-hoc показатель, зарегистрированный или ad-hoc
расчёт, форма, полный финансовый анализ либо сравнение двух сохранённых
срезов одного эмитента. Это основной UI-вход для семи GoalType; старые
`aifa-extract`/`aifa-analyze` остаются только совместимыми shortcuts.

## Что нужно на входе

Обёртка уже доставила OCR-текст и метаданные (`owner_id`, `case_id`,
`document_id`) до старта команды — их называть НЕ НАДО. От тебя нужен только
буквальный запрос пользователя (`--query`) — классификацию (извлечь/
посчитать, зарегистрированный/свой показатель) делает не эта команда, а
настоящий модельный вызов внутри неё.

## Если входа нет

Тип компании не назвали — определится по тексту отчёта. Ячейка не названа —
определится по классификации. Само содержимое `--query` обязательно: без
него команда не запустится.

## Порядок работы

КОМАНДА СИНХРОННАЯ, возвращает готовый результат, а не id фонового процесса.

`FE_PROGRESS_NONCE=<нонс> bash .shelf/aifa_station_skills/aifa-metric/scripts/metric_run.sh --doc-id <doc_id> --query "<запрос пользователя буквально>" --cell <ячейка>`

Передавай `--query` ДОСЛОВНО, как спросил пользователь, — не пересказывай и
не сокращай до кода показателя. Разбор строки в показатель/формулу делает
`intent.parse`, а не ты.

Допустимые флаги:

- `--company-type bank|non_financial` — только явное переопределение
  пользователя.
- `--cell <ячейка>` — если классификация уже известна ходу.
- `--out-json ./metric.json` — путь итогового manifest-файла.
- `--nonce` — внутренняя альтернатива `FE_PROGRESS_NONCE`, тебе называть не
  нужно.

## Правила

Не извлекай число из stdout вручную и не пересчитывай его. Один запрос — один
корневой результат. Если пользователь просит несколько отдельных показателей,
уточни один показатель либо попроси форму целиком тем же входом.
Отказ с кодом `intent_ambiguous` значит, что модель не смогла однозначно
понять запрос, — перескажи пользователю, что именно неясно, и переспроси
буквальными словами отказа, не придумывай значение сам.

## Вывод

Первая строка — краткое presentation-only резюме. `metric.json` —
типизированный manifest с паспортом запуска и ровно одним корневым результатом:
`extracted_metric`, `calculated_metric`, `form_output`, `report_output`,
`period_change_report` либо `file_artifact`.

## Границы навыка

Не для отчёта, которого ещё нет в системе: сначала загрузка документа.
`MONITOR_CHANGES` работает по одному документу: код сравнивает периоды внутри отчёта
(таблица Δ и Δ %), а модель пробует объяснить изменения; сохранённые снимки и
предыдущие ходы не нужны, но уже извлечённые в этом Case показатели переиспользуются.
Остальные шесть GoalType из общего каталога пока дают явный `unsupported_goal_type`,
без legacy fallback.
