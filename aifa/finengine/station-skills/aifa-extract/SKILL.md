## Когда

Только внутренний/совместимый вызов с уже известным `intent_kind=form`.
Обычный текст пользователя, включая просьбу заполнить форму, направляй в
`aifa-metric`: там обязательно выполняется настоящий `intent.parse`.

Нужны числа из отчётности, рассчитанные показатели, форма роли или XLSX.
Извлечение и формулы выполняются в одном `PlanGraph`; отдельный расчётный
навык после этого пути не запускай.

## Что нужно на входе

Обёртка уже доставила OCR-текст и метаданные (`owner_id`, `case_id`,
`document_id`) до старта команды — их называть НЕ НАДО. От тебя нужны только:
роль (`--role`, по умолчанию `other`), при точечном заказе — перечень
показателей (`--metrics`), при неизвестном типе компании — `--company-type`.

## Если входа нет

Роль не назвал пользователь — работает `--role other`: движок читает полный
реестр ячейки. Явный список показателей не назвали — извлекается всё, что
знает ячейка; узкий заказ (`--metrics`) сужает состав и время работы, но не
обязателен.

## Порядок работы

КОМАНДА СИНХРОННАЯ, ИДЁТ 6–25 МИНУТ и возвращает готовый результат, а не id
фонового процесса.

`FE_PROGRESS_NONCE=<нонс> bash .shelf/aifa_station_skills/aifa-extract/scripts/extract_run.sh --doc-id <doc_id> --role <role> --cell <ячейка> --out-json ./metrics.json`

Перед узким заказом ОБЯЗАТЕЛЬНО открой справочник ячейки
(`method/catalogue/`) и проверь точные имена показателей — иначе неизвестное
имя молча выпадет из состава.

Допустимые флаги:

- `--metrics "SALES_REVENUE,EBITDA"` — узкий заказ уже зарегистрированных
  показателей, имена через запятую в кавычках.
- `--company-type bank|non_financial` — только явное переопределение
  пользователя.
- `--out-xlsx ./result.xlsx` — создать файл выгрузки из того же результата.
- `--segments auto|on|off`, `--basis-full` сохранены для совместимости с
  прежними вызовами; состав production-графа решают Target, замороженный
  реестр и роль, а не эти флаги.
- `--nonce` — внутренняя альтернатива `FE_PROGRESS_NONCE` для transport
  wrapper, тебе называть не нужно.

## Правила

Не извлекай числа из stdout/markdown вручную и не пересчитывай их. Не
запускай отдельный расчётный навык после этого пути и не повторяй прогон.
`--extra-metrics`/`--extra-calculated` больше не источник определений —
их передача завершается отказом; для собственных показателей нужен обычный
запрос новым показателем, не флаг станции.

Если в ответе стоит предупреждение «роль ... не заведена», перескажи его
пользователю прямо: узкая роль не сузила состав, отчёт читается по всей
ячейке.

## Вывод

Первая строка — сколько ЗНАЧЕНИЙ найдено из скольких запрошено; она и есть
итог, а не число строк таблицы ниже. Меньше половины найденного — отдельное
предупреждение, скажи о нём пользователю прямо. `metrics.json` — типизированный
manifest (паспорт запуска + результат + при заказе файл), не плоский список
чисел; таблицу из stdout можно показать как есть.

## Границы навыка

Не для финансового анализа/вывода — за этим отдельный навык. Не для отчёта,
которого ещё нет в системе, — сначала загрузка документа.
