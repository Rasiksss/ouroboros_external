# Нерушимые продуктовые решения

> Общий файл — читать в начале **каждой** сессии, независимо от того, какой срез реализуется. Источник: §1 полного плана. Ничего здесь не подлежит переосмыслению внутри сессии реализации; если решение кажется неверным — это повод остановиться и спросить владельца, а не переопределить его кодом.

# 1. Нерушимые продуктовые решения

1. Финансовый анализ держится на трёх обязательных блоках: **классификация → извлечение/расчёт → финансовый анализ**. Ни один последующий блок не имеет права самостоятельно переопределять результат предыдущего.
2. Классификация выполняется один раз на запуск и фиксируется в `RunPassport`. Повторное определение профиля ниже по конвейеру допускается только как диагностическая проверка расхождения.
3. Все числа, на которых строятся выводы, должны происходить из единой доказательной базы. Аналитическая модель не извлекает финансовые числа второй раз из исходного текста и не выполняет скрытые арифметические расчёты. *(На время MVP симбиоза с ouroboros отложено — ADR-0040 `aifa-symbiosis/architecture/adr/`; возврат — по итогам тестирования MVP.)*
4. Извлечённые факты, рассчитанные факты, цитаты, условия, структурированные таблицы, внешние факты и пользовательские поправки должны иметь единый механизм идентичности, происхождения и версионирования.
5. Код выполняет хранение, маршрутизацию, преобразование, расчёты, проверки и сравнения. **Финансовое смысловое суждение формулирует модель по методике.** Код не должен скрыто превращаться в экспертную систему из сотен `if` с бизнес-вердиктами.
6. Продукт не выдаёт инвестиционных и иных рекомендаций. Граница сценария финансовой отчётности — анализ, объяснение, форма, файл и наблюдение за изменениями.
7. Шесть ролей из `roles/layouts.json` — реальные заказчики. Специфичные для заказчика определения, формулы, пороги и отображение должны становиться данными и слоями реестра, а не ветвлениями в коде.
8. ДГР и его форма являются полноценным типом результата. Пустые/недоступные строки формы не выбрасываются, если контракт формы требует их сохранить.
9. Любое выполнение, инициированное моделью, идёт через ограниченный профиль песочницы. Доступ к сети, файлам, коду и внешним системам не выдаётся атомам по умолчанию.
10. В проекте сейчас нет пользовательского трафика, поэтому миграция не строится вокруг постепенной раскатки. Новый функционал сначала полностью реализуется и встраивается в целевой маршрут разработки, затем проверяется на тестовом контуре и репрезентативном наборе данных. Старый путь допускается только как источник эталонного поведения для автоматического сравнения. После успешной проверки заменённый старый код удаляется. Два постоянных источника истины оставлять нельзя.
