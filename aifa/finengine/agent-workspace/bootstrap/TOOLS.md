# Заметки по инструментам

Как звать инструмент — сказано в его схеме, порядок вызова — в файле навыка.
Дублировать это здесь значит завести второе место для одного правила.

Здесь только то, что не принадлежит ни схеме, ни навыку: **свойства комнаты, в
которой исполняются твои команды**. Они одинаковы для всех навыков, и не зная
их, ты потратишь ход на борьбу с песочницей вместо работы.

## Комната запечатана — и это штатно

Сети наружу из комнаты нет. Вызовы модели во время работы скриптов идут
файловым мостом; долгие команды при этом молчат — «(no new output)» с растущим
временем это работа, а не зависание.

* **`.model-rpc/` не читай и не трогай** — это служебный канал моста, во всех
  навыках одинаково.
* **Полка уже доставлена в комнату и РАСПАКОВАНА в каталог `.shelf/`** —
  распаковывать её не нужно, команды навыков работают сразу. Если каталога
  `.shelf/` вдруг нет (доставка споткнулась), распакуй сам и продолжай:
  `python3 -m zipfile -e .shelf.zip .shelf/`
* **Полка видна только из `exec`.** Файловый тул `read` — другая файловая
  система: на любой путь `.shelf/…` он отвечает ENOENT, сколько ни повторяй.
  Это не «файл потерян» — читай командой.

## Где ты находишься, когда зовёшь `exec`

Команда исполняется **уже в рабочей папке комнаты**. Пути в телах навыков —
относительные, и они верные как есть.

* **Не добавляй `cd`.** Ни в каком виде.
* **Каталога `/workspace` не существует.** Файловый API (`read`, загрузка
  файлов) показывает пути вида `/workspace/…` — это ЕГО корень. У `exec` другое
  пространство имён, и `/workspace` оттуда недостижим. Искать там нечего.
* **Не нашёл файл — дай `ls -la` без пути.** Она покажет, что реально лежит
  рядом. Это дешевле любого `find`.

## Каких инструментов НЕ СУЩЕСТВУЕТ — имена не угадывай

Поиска по файлам ОТДЕЛЬНЫМ инструментом нет: ни `search`, ни `grep`, ни
`find`, ни `ls` как тулов не существует. Вызов несуществующего имени вернёт
отказ — а отказ посреди работы обрывает весь ход, и пользователь не получает
ничего.

**Искать в файлах — только командой через `exec`:**

| хочется | правильная команда |
|---|---|
| найти слово в справочнике | `grep -i "долг" .shelf/aifa_station_skills/aifa-extract/method/catalogue/ifrs_nf_ru.md` |
| проверить расчётную формулу | точная команда — в теле навыка расчёта, шаг 1 |
| посмотреть, что лежит рядом | `ls -la` (как команда exec, не как тул) |

⚠️ Куплено дважды: 30.08 (Татнефть) и 31.08 (НОВАТЭК) — модель звала тул
`search`, получала отказ и завершала ход, не сделав работу. Оба раза
пользователь остался без ответа и без объяснения.

## Какие команды песочница отбивает

Отказ выглядит так: `exec preflight: complex interpreter invocation detected;
refusing to run without script preflight validation. Use a direct
python <file>.py or node <file>.js command`.

Правило ядра срабатывает, когда в ОДНОЙ команде совпали три вещи: вызов
`python`/`node`, составной синтаксис (`&&`, `;`, конвейер) и запуск скрипта.
Практический вывод:

| так — отобьёт | так — пройдёт |
|---|---|
| `cd /workspace && python3 x.py` | `python3 x.py` |
| `python3 a.py && python3 b.py` | два отдельных вызова |
| `python3 x.py \| tee log` | `python3 x.py` |

На `bash файл.sh` правило не распространяется — команды навыков этой формы
безопасны и составными их делать всё равно не надо.

## Если команда отбита

**Не чини её и не ищи обходов.** Отказ песочницы — это форма команды, а не
поломка системы: убери `cd`, убери `&&`, разбей на два вызова. Читать исходники
скриптов, искать файлы по абсолютным путям и переписывать команду в третий раз
не нужно — ход конечен, и потратив его на это, ты не сделаешь работу.

⚠️ Куплено прогоном 19.08 (Банк «Санкт-Петербург»). Модель сама дописала
`cd /workspace &&` к команде плана, получила два отказа, четыре раза искала
файлы в несуществующем каталоге и закончила ход, не начав извлечение.
Пользователь ждал пятнадцать минут и не получил ничего.
