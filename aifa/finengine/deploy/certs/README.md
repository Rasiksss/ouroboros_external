# Сертификаты для российских государственных сайтов

Зачем: у `rosstat.gov.ru` сертификат выдан удостоверяющим центром Минцифры,
которого нет в штатном хранилище (`certifi`). Без этих двух файлов проверка
падает с `CERTIFICATE_VERIFY_FAILED`, хотя сайт полностью доступен и отдаёт
данные.

| файл | что это | откуда взят |
|---|---|---|
| `russian_trusted_root_ca.pem` | корневой центр Минцифры, самоподписанный, до 2032-02-27 | https://gu-st.ru/content/Other/doc/russian_trusted_root_ca.cer |
| `russian_trusted_sub_ca_ssl_2024.pem` | промежуточный ДЛЯ SSL, выпуск 2024 | адрес из самого сертификата Росстата (расширение Authority Information Access): http://nuc-cdp.digital.gov.ru/cdp/subca_ssl_rsa2024.crt |

⚠️ ПОЧЕМУ ПРОМЕЖУТОЧНЫХ ДВА РАЗНЫХ. В сводном наборе Минцифры
(`russiantrustedca.pem`) лежит ДРУГОЙ промежуточный — ключ `D1:E1:71…`. Он
цепочку Росстата НЕ закрывает: там нужен `77:3D:D9…`, и сервер его не
присылает. Правильный адрес указан в самом сертификате сайта, в расширении
Authority Information Access. На это ушло четыре неудачных попытки, прежде чем
я догадался прочитать расширение вместо перебора публикаций.

⚠️ ДОВЕРИЕ ТОЧЕЧНОЕ, А НЕ ГЛОБАЛЬНОЕ. Эти центры подключаются ТОЛЬКО для
адресов из `_RU_GOV_HOSTS` (`finengine/net/ru_gov_tls.py`). Установка в общее
хранилище означала бы, что государственный центр может поручиться за ЛЮБОЙ
домен, включая OpenRouter и Tavily, — это настоящая поверхность для перехвата
нашего же трафика.

Проверить, что цепочка жива (промежуточный истекает раньше корневого):
    openssl x509 -in russian_trusted_sub_ca_ssl_2024.pem -noout -dates
