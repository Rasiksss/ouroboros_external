Решение: оба файла публичные и меньше 5 МБ, поэтому лежат в репозитории. В каждой записи есть
`sha256` загруженного файла (`documents[].sha256`), по нему видно, на каком документе снята запись.
Не подтверждено: что копии на стенде (QA-проект частей 12 и 15) побайтно те же — записывающий клиент
загружает файлы из репозитория в новый проект, так что запись не зависит от копии на стенде.

## Как записать

```bash
export AIFA_GOLDEN_BASE_URL=<адрес API старого dev>   # check_stand пускает только dev и loopback
export AIFA_GOLDEN_USER=...  AIFA_GOLDEN_PASSWORD=... # не в git
for n in A1 A2 A3 A4 A5 A6 A7 A8 S1 S2 S3 S4 S5; do
  python aifa/tests/golden/golden_cli.py stability aifa/tests/golden/$n/scenario.json \
    --out-dir aifa/tests/golden/$n --text presence
done
python aifa/tests/golden/golden_cli.py schemas --out aifa/contracts/events \
  aifa/tests/golden/*/*-run?.json
```

`stability` записывает сценарий дважды и сравнивает; `--text presence` — потому что текст живой
модели каждый раз иной. Прогон длинный (A2, A3, S1 — 5–8 минут на ход): с локальной машины ход может
рваться — тогда запускать на сервере под `nohup`. Запись — данные: вручную не правится, нужна
правка — перезапись сценария.

## Разрешённые различия

| Различие | Основание | Где в коде |
|---|---|---|
| `thinking` отсутствует; `text_delta` нарезан иначе (в новой системе один кусок) | ADR-0015 | `golden_normalize.py`, `golden_compare.py` |
| Загрузка `.xls`/`.doc` отвечает ≥ 400 вместо 200 | ADR-0026 | `golden_compare.py` (`REFUSED_FORMATS`) |

**P6 — принимает ли нынешний AIFA XLS/DOC.** Да, по коду: `POST /documents/upload`
(`finengine/api/main.py`, `upload_document`) не проверяет расширение — для `.pdf` есть ворота по
сигнатуре, для остальных файл принимается (200, `doc_id`) и кладётся в хранилище; фоновый разбор
(`_parse_doc_in_background`) для всего, кроме `.pdf`, `.txt`, `.md`, завершается без текста, и
`GET /documents/{id}/status` остаётся `processing: true`. Экран предлагает только PDF
(`chat-pane.tsx`, `accept=".pdf,application/pdf"`). Поэтому различие ADR-0026 («старый — 200, новый —
отказ») уже учтено сравнением (шаг 05; тест `test_a_refused_xls_upload_on_the_new_side_is_an_allowed_difference`).
Пробная загрузка небольшого файла на стенде **не выполнена** (доступ к стенду отклонён) — P6 закрыт
по коду, проба остаётся к записи наборов. Следствие для записи: сценария с XLS/DOC в наборе нет;
`_wait_parsed` клиента на таком файле ждал бы текст до таймаута.
