# Подставная модель

OpenAI-совместимый сервер, который отвечает ouroboros **по сценарию**, а не настоящей моделью. Он
делает ход ouroboros детерминированным: одинаковый запрос — одинаковый ответ, без денег и сети
(`ARCHITECTURE.md` §2). Подставляется только модель; всё остальное в ouroboros настоящее.

Это тестовый инструмент, не продукт: сопоставление нарочно глупое. Правила идут по порядку,
срабатывает **первое**, у которого выполнены **все** условия. Никакой «похожести» нет.

## Сценарий

Файл JSON. Рабочие примеры, оба проходят живой ouroboros профиля `contract`:
`aifa/tests/contract/scenarios/hello.json` (ответ текстом) и `tool_round.json` (вызов инструмента,
затем ответ):

```json
{
  "name": "tool_round",
  "rules": [
    {
      "id": "title-by-light-model",
      "when": {"model": "stub-light"},
      "reply": {"text": "Инструменты"}
    },
    {
      "id": "call-tool",
      "when": {"model": "stub-main", "user_contains": "покажи инструменты", "round": 1},
      "reply": {"tool_calls": [{"name": "list_available_tools", "arguments": {}}]}
    },
    {
      "id": "answer-after-tool",
      "when": {"model": "stub-main", "user_contains": "покажи инструменты", "round": 2},
      "reply": {"text": "Список инструментов получен."}
    }
  ]
}
```

| Поле правила | Смысл |
|---|---|
| `id` | обязателен, уникален; журнал называет по нему сработавшее правило |
| `when` | обязателен; `{}` — «любой запрос» (универсальное правило пишут явно) |
| `reply` | ответ: `text` и/или `tool_calls`, либо `error` (смешивать `error` с остальным нельзя) |

Условия `when` (все необязательны, соединены «и»):

| Условие | Выполнено, если |
|---|---|
| `model` | имя модели в запросе равно значению (`stub-main`, `stub-light`, `stub-fallback` — так их называет профиль `contract`) |
| `user_contains` | реплика пользователя — **первое** сообщение роли `user` в запросе — содержит подстроку (с учётом регистра) |
| `last_tool_result_starts_with` | последний результат инструмента (`role: tool`) в запросе начинается с значения |
| `round` | круг равен числу: 1 + число ответов модели (`role: assistant`) в запросе |

Почему первое `user`, а не последнее: запрос ouroboros — одна задача, история чата лежит в
системном сообщении. После круга с инструментом ouroboros сам дописывает `user`-записку
(«[SYSTEM RUNTIME NOTE: TOOL OUTCOME LEDGER]…»; так же `[ROUND_LIMIT]` и др.) — реплика
пользователя, круг и результат инструмента от неё не меняются.

Ответы:

- `{"text": "…"}` — обычный ответ, `finish_reason: stop`;
- `{"tool_calls": [{"name": "…", "arguments": {…}}]}` — вызовы инструментов в формате OpenAI
  (`arguments` уходит строкой JSON), `finish_reason: tool_calls`; `text` рядом допустим;
- `{"error": {"status": 503, "message": "…"}}` — ответ-ошибка с этим статусом.

Опечатка в поле, правило без `when`, пустой ответ и повтор `id` отклоняются при загрузке с именем
правила — сценарий не должен молча стать «универсальным».

**Нет совпадения** — сервер отвечает 400 с текстом: что спросили (модель, круг, реплика, результат
инструмента) и какие правила есть. Ouroboros повторяет такой запрос трижды, переходит на запасную
модель (ещё три) и отвечает пользователю «All models are down» с этим текстом: тест падает за
несколько секунд с читаемой причиной, а не висит. Запрос без правила виден в журнале
(`rule: null`).

## Что делает ouroboros с моделью

- Клиент **не потоковый** (`ouroboros/llm/providers/openai_compat.py`): `stream: true` сервер
  отклоняет с понятным текстом — значит, клиент изменился.
- Основная модель получает системное сообщение (список частей) и реплику пользователя
  дословно; лёгкая модель после хода называет беседу — для неё нужно правило (в примере первое).
- Ошибку основной модели (в том числе ответ-`error` сценария) ouroboros повторяет трижды, затем
  переходит на запасную (`stub-fallback`) — это поведение настоящего ouroboros; правила под него
  пишут с учётом трёх запросов.

## Запуск и журнал

Сервер стандартной библиотекой, без зависимостей; в профиле `contract` он стоит в контейнере
(`aifa/deploy/dev/compose.contract.yml`, порт `127.0.0.1:18182`). Вручную:

```bash
cd aifa/tests && python -m stub_model --port 8000 [--scenario contract/scenarios/hello.json]
```

| Путь | Назначение |
|---|---|
| `POST /v1/chat/completions` | ответ по сценарию |
| `GET /v1/models` | пустой список (ouroboros по этому пути не ходит) |
| `GET /health` | для healthcheck |
| `PUT /_scenario` | заменить сценарий (неверный отклоняется, прежний остаётся) |
| `GET /_journal`, `DELETE /_journal` | журнал запросов: `seq`, `model`, `round`, `user`, `last_tool_result`, `tools`, `messages`, `rule`; очистка |

Со стороны теста — `stub_model.client.StubModelAdmin`: `use_scenario`, `journal`, `clear`,
`saw(text)` («модель увидела»), `unmatched()`. «Модель не увидела» — `not saw(text)`.

Токены в `usage` — грубая оценка по длине (4 знака на токен): настоящей модели нет, стоимость не
считается.
