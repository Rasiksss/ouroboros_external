# 23 · Планирование подзадачей, приёмка корнем · 22.10.2026

## Сделано

Реализована только первая согласованная часть, ADR-0061. Корень поручает составление плана
навыку `distribution:aifa-plan-author` через существующий `schedule_task`. Автор получает исходный
запрос, уточнения, ссылки, возможности, ограничения и текущую ревизию; возвращает полный JSON
результатом подзадачи. Короткий `aifa_report(done)` для передачи плана не используется.

Инструмент `task_plan` предоставляет схему, чтение, принятие предложения, запись попытки,
приёмку результатов по критериям и полное/частичное завершение. Только корень может писать.
Принимается результат завершённой прямой подзадачи той же области. Требования связаны с шагами,
входами, зависимостями и критериями. Техническая проверка формы не подменяет смысловое решение корня.

План хранится в runtime PostgreSQL (миграция 0034) с обязательным шифрованием ключом credentials,
привязкой к OwnerScope и корневой задаче. Версия состояния защищает от конкурентной записи;
история ревизий, наблюдений и решений сохраняется. Пересмотр не сбрасывает активные попытки.
Новая ревизия сохраняет неизменённые принятые шаги лишь при сохранении требований и входных зависимостей.

В агентском пути AIFA больше не принимает пользовательские plan/files как критерий полноты.
Служба сохраняет техническую проверку наличия опубликованных файлов. Корень проверяет содержание
файлов и полноту требований, после чего отдельно закрывает план и цикл AIFA.

## Что и почему

Планировщик предлагает, корень принимает. Это оставляет семантическую проверку у оркестратора
и позволяет явно увидеть пропуски вроде презентации или второго листа Excel до исполнения.
Состояния `awaiting_review` и `accepted` разделяют результат исполнителя и решение оркестратора.
Приёмка ссылается на конкретную попытку, точные ссылки результата и наблюдения по всем критериям;
успешный runtime сам по себе не означает, что пользовательская задача выполнена.

Инструмент и хранилище общие для ouroboros; они не импортируют AIFA. Инструкции делегирования
относятся к навыкам AIFA. Нового LLM-сервиса, альтернативного цикла исполнения и HTTP API нет.
Физическая достоверность наблюдения остаётся ответственностью корня: инструмент проверяет
связность записи, но не открывает Excel и не оценивает презентацию за оркестратора.

## Проверки

- До изменения подтверждено падение регрессии приёмки файлов агентского пути AIFA.
- 13 тестов нового инструмента с настоящим PostgreSQL: предложение → принятие → попытка →
  наблюдения → завершение, восстановление состояния новым репозиторием, чужая область,
  права подзадачи, устаревшая версия, конкурирующие записи, неполная приёмка,
  несовпавшие ссылки результата, пересмотр активной попытки, шифрование и отсутствие ключа.
- Инструмент и общий контрактный набор: 112 passed.
- Затронутые тесты службы, навыков, архитектуры и compose: 314 passed.
- Linux: `bash scripts/check.sh --fast` проходит (ruff, mypy: 573 файла).
- Linux: полный набор навыков — 198 passed.
- Полный `scripts/check.sh` запускался, но не проходит headless: 319 passed / 2 failed.
  Оба дефекта воспроизведены на исходной версии: `.claude/rules` является обычным файлом,
  а существующие пакеты AIFA не покрыты картой владельцев. Их исправление вне этой задачи.
- Полный Linux unit/regression: 7228 passed / 1 baseline failed / 22 skipped; новых падений нет.
- Отдельное прежнее падение `test_the_local_image_copies_every_source_tree_the_entrypoints_import`
  воспроизведено исходным тестом: `Dockerfile.local` не копирует `aifa`.

Windows не использовалась как итоговая среда для POSIX subprocess-тестов. Проверки выполнены
в изолированном Linux-контейнере с init, установленным проектом и отдельной тестовой БД.

## Независимое ревью

Чистый контекст: агент `/root/review_task_planning`, с проверкой INVARIANTS и Coding Rules.
В первой итерации найдены и исправлены: сброс активной попытки при пересмотре,
необязательное шифрование плана и устаревшая подсказка службы про plan/files.
После исправлений блокирующих замечаний нет; ревьюер самостоятельно выполнил 13 тестов.

## Границы и оставшееся

Каталог атомов, новая система исходов и восстановление графов (пункты 2–4), кэш методик
и изменение состава анализа не реализовывались. Сохранение плана не является checkpoint
внутренних операций хода: устранение повторного выполнения относится к отложенной работе.

Живой LLM-прогон исходного PDF, повтор dev-прогона и выкатка не выполнялись. Dev и prod не менялись.
До зелёного общего gate полная Definition of Done не закрыта (P134). Дополнительной чистки нет.
