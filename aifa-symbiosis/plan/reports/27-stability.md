## Исправления

1. **Выбор поиска терялся на границе хода.** `QueryRequest.web_search` не попадал
   в `TurnRecord`; внутренние HTTP-инструменты использовали default=True. В `d0e752a`
   выбор сохраняется и применяется на время вызова. Фоновые задания и потоки наследуют
   контекст; `finally` восстанавливает прежнее значение. Старые записи закрыты для сети.
   ADR-0066. Исправление выкачено, ready/health/build-id/login прошли.
2. **Живой прогресс буферизовался при сжатии.** Через Next запрос с gzip получает
   gzip-ответ, но не отдаёт первую распакованную строку за 8 с; identity — за 0,007 с.
   `709208b` добавляет `no-transform` в типизированный SSE. Установленный middleware
   Next учитывает этот заголовок. ADR-0068. Выкачено: Content-Encoding отсутствует даже
   при Accept-Encoding:gzip, первая строка за 0,015 с; новый UI показывает прогресс вживую.
3. **Приёмка не проверяла смысл источников.** ADR-0070 и b058bef уточняют инструкции
   корня: не менять отсутствующий операнд без подтверждения эквивалентности, различать
   факт/прогноз и периоды, проверять ссылки, формулы и выводы файла. Это не доказательство
   исправления качества: требуется повторный фактический Excel.

Обе правки получили независимое ревью без блокеров с проверкой инвариантов и Coding Rules.
Соседняя чистка не выполнялась.

## Что осталось

SSH и туннель восстановлены; владелец подтвердил, что другая сессия не меняет dev.
Устойчивый Excel из исходного сценария не получен ни на одной модели. Открыто:

1. Итог корня расходится с извлечёнными артефактами (выручка). Нужно понять, откуда
   взялись «85,91/100,01» — из текста последнего хода или из другого источника, и
   запретить выдачу чисел, которых нет в артефактах.
2. Чистый долг считается из балансовых строк; реестр/сценарий его не извлекает, а корень
   принимает «не найден» за конец. Решение (расчётный показатель с объявленным
   определением) — за владельцем: меняет поведение, требует ADR.
3. При частичных данных корень должен собрать файл с пометками пропусков, а не закрывать
   план без файла.
4. Ставки ЦБ: страница `hd_base/keyrate` без JS отдаёт оболочку; нужен другой источник
   (например, XML/`DailyInfo` ЦБ или таблица на cbr.ru с параметрами), иначе годовая
   ставка остаётся неподтверждённой.
5. Планирование: три отклонения из четырёх — формат предложения (текст вокруг JSON,
   id критериев). Поправить инструкцию автора плана, не ослабляя схему.

Полные ворота остаются красными, отдельного полного сравнения их падений с исходной
базой нет. Отсутствие данных не заменять выдуманной годовой корреляцией.
