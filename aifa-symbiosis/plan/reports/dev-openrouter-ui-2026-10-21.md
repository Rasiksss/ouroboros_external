# Dev: OpenRouter через infproxy и два UI-кейса

21.10.2026, время ниже московское (UTC+3). Исполнитель: Codex.

Последующее указание владельца: после этих прогонов модель переключена на GLM-5.3;
актуальное состояние — [отдельный отчёт](dev-glm53-admin1-2026-10-21.md).

**Подключение работает. Из двух кейсов один прошёл численную проверку, один не прошёл.**
Завершение runtime-задачи не означает прохождение финансового кейса.

## Подключение и проверка

Только живое окружение compose-проекта `aifa-sym`:

- Endpoint обоих процессов: `http://172.17.0.1:8820/v1`.
- Модель всех активных ролей: `deepseek/deepseek-v4-flash`.
- Ouroboros: `cloudru::deepseek/deepseek-v4-flash` для основной, лёгкой и запасной
  роли, адрес адаптера переопределён окружением. Префикс обозначает адаптер.
- Engine: разбор, планировщик, locate, read.value и новости — та же модель.
- Клиентский токен перенесён на сервере из разрешённой владельцем настройки старого dev.
  Значения ключей не выводились; оба env и их резервные копии имеют права 600.
- Резервные копии: `~/aifa-sym-engine.env.before-openrouter-20261021-115010` и
  `~/aifa-sym-ouroboros.env.before-openrouter-20261021-115010`.
- Пересозданы только `aifa-sym-engine-1` и `aifa-sym-ouroboros-1`, без сборки;
  оба healthy. Общий infproxy, Caddy, prod и старые приложения не изменялись.

До переключения реальный `chat/completions` через infproxy: HTTP 200 за 2,47 с,
ответ `OK.`, модель в ответе `deepseek/deepseek-v4-flash`.
В HTTP-журнале двух корней — 29 вызовов этого endpoint, все HTTP 200.
Это число не включает отдельные LLM-вызовы службы.

Идентификатор выбран исполнителем как ближайший разрешённый Flash.
`deepseek-ai/DeepSeek-V4-Pro` у существующего infproxy направляется в Cloud.ru,
поэтому для проверки OpenRouter он не использован. Решение — [ADR-0056](../../architecture/adr/0056-dev-openrouter-infproxy.md).

## Как выполнялись кейсы

Вход через браузер в `http://127.0.0.1:13000/v2`, SSH-туннель к dev, учётка `qa-a`.
Два новых чата; в каждом через UI прикреплён стандартный
`plan/uitest/fixtures/Novatek_FS_12m2021_RUS.pdf`, затем отправлен запрос.
API использовался после отправки для сохранения событий именно этих ходов;
запуска сценариев через API не было. Временная локальная копия пароля qa-a удалена.

Пользователь случайно переключил первую вкладку во время первого хода.
Первый ход продолжил работу на сервере; его итог проверен реплеем по run_id.
Финальный ответ первого хода в исходной вкладке глазами не подтверждён.
Второй ход выполнен в отдельной вкладке, финал и артефакты проверены в UI.

## Проверка чисел по приложенному PDF

Страница 11, «Консолидированный отчет о прибылях и убытках», млн рублей.
Текст извлечён pypdf, страница отрендерена Poppler и проверена визуально.

| Показатель | 2020, PDF | 2021, PDF | Что ответил S1 за 2020 / 2021 |
|---|---:|---:|---:|
| Итого выручка от реализации | 711 812 | 1 156 724 | 710 753 / 1 056 466 |
| Прибыль до налога на прибыль | 129 596 | 501 204 | 202 350 / 328 370 |

Контроль: рост выручки `(1156724/711812−1)×100` = **62,504144%**;
Brent `(70,86/41,96−1)×100` = **68,875119%**;
отношение изменений = **0,9074996**.
Рентабельность прибыли до налогообложения: 2020 **18,20649%**, 2021 **43,32961%**.

S1 обошёл службу: в HTTP-журнале нет `aifa_goal`, `aifa_move`, `aifa_finish`;
есть прямое исполнение кода в Workstation и скачивание файла внутри runtime.
Поток службы содержит обещание `novatek_financials.xlsx`, но ни одного `file`.
Доставку XLSX, его листы и формулы проверить нельзя. Самостоятельно исправленный
Excel вместо результата агента не создавался: это скрыло бы результат теста.

S2 прошёл через `aifa_goal` → `aifa_move` → `aifa_finish`; UI показал два
артефакта SALES_REVENUE, два хода планировщика, ноль попыток автора.
Оба значения выручки и три результата вычислений совпадают с контролем.
Замечания: LaTeX виден исходным текстом; «дуговая эластичность» не соответствует
использованной формуле процентов к базовому году; утверждения о неполном переносе
цен и сдерживающих факторах не доказаны двумя наблюдениями.

## Что осталось

Подключение оставлено на OpenRouter. Код, навыки, пределы цикла и образы не менялись.
Примеры окружения и F9 пока закрепляют Holy API (ADR-0055): их синхронизация
не выполнена в рамках живого переключения; зелёный F9 не подтверждал бы этот endpoint.
Полные кодовые ворота не запускались: изменения — серверное окружение и отчёты.

Отдельная работа: воспроизвести обход навыка и потерю публикации файла в S1,
исправить путь извлечения/файла и повторить Excel-кейс. UI-показ LaTeX и точность
пояснений S2 также требуют исправлений. Новый прогон автора и приёмка шага 18
этими двумя кейсами не закрыты. Дополнительного рефакторинга не выполнялось.
