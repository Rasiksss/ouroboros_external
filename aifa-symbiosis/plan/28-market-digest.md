# Шаг 28. Рыночный дайджест как сценарий службы

Дата: 28.10.2026. Статус: ADR-0098 принята владельцем 28.10.2026; код реализован (28.0–28.4),
инструкции агента обновлены (28.5), живой dev-smoke не выполнялся — ждёт сигнала владельца.
Основание: [ADR-0098](../architecture/adr/0098-market-digest-scenario.md).

## Результат, который должен получить пользователь

Запрос «Запусти дайджест за неделю» без приложенного отчёта:

1. Агент открывает `aifa_open(mode="market")` и получает состояние без паспорта отчёта.
2. Принимает план по действующему порядку и вызывает
   `aifa_move(goals=[{"ref":"g1","scenario":"market_digest","parameters":{"since_hours":168}}])`.
3. Служба фиксирует окно и запускает встроенный сценарий в своём задании.
4. После 240 с ответ — `ЖДИ job=...`; `aifa_wait` ждёт это же задание без нового сбора.
5. Агент получает статус и id `DigestOutput`, читает результат через `aifa_state`, принимает
   фактический результат и закрывает цикл обычным `aifa_finish`.
6. Читатель видит период, время сборки, источники и предупреждения. Повторное чтение даёт тот же выпуск.

Запрет сети и неполный сбор видны как ограничения, а не как успешный полный дайджест.

## Область изменений

Только `aifa/`, `skills/aifa-*`, `aifa-symbiosis/`. Изменения ядра ouroboros, OpenClaw, отдельный
MCP-сервис, расписания, смена моделей корня и выкатка на prod не нужны.
Текущая ветка содержит чужие незакоммиченные файлы: их не добавлять и не перемещать.
Для реализации — отдельная ветка `sym/28-market-digest` от согласованной актуальной базы;
этот документ не объявляет текущую рабочую ветку такой базой.

Используется уже перенесённый `aifa/finengine/src/finengine/skills/news/`. Исходная
`origin/prod-daily-calendar` AIFA-CLAW — только источник сравнения; не переносить пакет вслепую.
До правок кода прочитать правила путей и запустить `resolve_rules.py` для точного списка файлов.
Поведение, покрытое OpenSpec, меняется только после соответствующего change.

## 28.0. Контракт и базовая линия

Действия:

- Принять или уточнить ADR-0098. После принятия обновить `CONTRACTS.md` §3 (C3.3/C3.4/C3.9),
  архитектуру цикла, карту проверок и снимок схем в том же коммите с ADR по F13.
- Зафиксировать перед реализацией базовую линию затронутых тестов и ограничения окружения.
- Сверить локальный `news` с исходной веткой: коннекторы, клиенты моделей, хранение, кэши,
  ошибки классификации, даты, зависимости Chromium. Проверить, что импорты не запускают
  старые планировщики или OpenClaw.
- Утвердить формальный `DigestOutput`, перевод статусов в итог части цели, сетевой профиль
  встроенного исполнителя и сроки конвейера в пределах бюджета цикла.
- Зафиксировать `operation_id` в транспортном конверте и атомарную привязку задания по ADR-0098;
  отдельно — идентичность части `(цикл, ref)`, конфликт изменённых параметров и новый `ref`
  для нового запуска. Снимок публичных инструментов не получает аргумента `operation_id`.
- Межпрогонную историю Long list отключить для нового сценария; дедуп текущего пула сохранить.

Выход: принятый контракт, список конкретных файлов/проверок, исходные результаты тестов.
Документ со статусом «предложено» не является разрешением менять действующее поведение.

## 28.1. Рыночный цикл без документа

Точки изменения: `skills/aifa-engine/plugin.py`, `assistant/loop_opening.py`,
`assistant/goal_tools.py`, `assistant/loop_desk.py`, `skills/production_runtime.py`,
`skills/spec/dynamic_run.py`, `skills/spec/loop_state.py` и сохранение происхождения цикла.
Точный набор уточняется по прямым вызовам; соседний код не рефакторить.

Сначала тесты:

- `market` открывается с пустым `doc_ids`, без OCR, классификации и сетевого сбора;
- `report` по умолчанию сохраняет `ОТКАЗ нет_документа` и выбор активного из нескольких PDF;
- повтор открытия возвращает тот же цикл, смена режима отклоняется;
- режим, Case и отсутствие паспорта сохраняются после восстановления; старые записи читаются
  как `report`; `aifa_state` и `aifa_finish` не обращаются к отсутствующему паспорту;
- чужой владелец/ход и подзадача не могут открыть или подменить цикл.

Реализация: явный режим в том же механизме цикла; не заполнять паспорт фиктивными значениями.
Проверка завершения: API → настоящее открытие → сохранение/восстановление → состояние/закрытие.

## 28.2. Часть цели и граф сценария

Точки: `contracts/intent.py`, тип результата в `contracts/`, `skills/spec/agent_goals.py`,
`skills/atoms/intent.py` (`root_from_goal`), каталог/исполнители встроенных атомов,
`skills/production_runtime.py` (`GoalChannel`), `skills/aifa-engine/plugin.py`.

Сначала тесты:

- `market_digest` принимается только в `market`, прежние сценарии — только в `report`;
- `parameters.since_hours` принимает 6 и 336, по умолчанию 48; неверный тип, лишние поля,
  неизвестный сценарий и поля отчётности отклоняются до исполнения;
- общие `ref`/`depends_on` проверяются по прежним правилам;
- граф строится без паспорта; встроенный узел требует сетевой профиль и возвращает `DigestOutput`;
- план строится по коду сценария без классификатора сообщения и вложенного агентного цикла;
- окно и ключ результата разделяют разные запросы/Case и не сдвигаются при ожидании.

Проверка завершения: реальная схема плагина → разбор API → GoalChannel → исполняемый граф;
F4 и бюджет схем, прежние графы извлечения, расчёта и формы.

## 28.3. Адаптер существующего новостного конвейера

Точки: новый адаптер под `skills/news/`, существующие `pipeline.py`, `collect.py`, `classify.py`,
`macro_indicators.py`, `render.py` и композиция зависимостей службы. Меняются только места,
которые необходимы для гарантий нового сценария; старые API не переводятся автоматически.

Сначала тесты с подставными источниками, моделью и часами:

- конвейер получает фиксированное окно; ни отбор, ни заголовок не вычисляют новое окно по ходу;
- `TurnRecord.web_search=false` запрещает все внешние запросы до их отправки;
- используются только источники серверного каталога, перенаправления также проверяются;
- владелец/Case берутся из вызова службы; чужие настройки, результаты и старые сценарии не читаются;
- новый самостоятельный запуск не скрывает событие из-за предыдущего дайджеста того же владельца;
- сетевой и модельный вызовы сохраняют трассу; секреты и пользовательские идентификаторы
  не попадают в произвольные внешние источники;
- `complete`, полезный `partial`, здоровый `empty`, отказ всех источников, сбой модели,
  корректный JSON неверной формы и пропущенные классификатором записи различаются;
- макроснимок явно сообщает период наблюдения и возраст; `first_seen` не выдаётся за релиз;
  дата обновления FRED не остаётся бессрочной датой публикации точки;
- учтены вызовы классификации и перевода, предупреждения не теряются при ошибке сохранения.

Проверка завершения: реальный адаптер с существующим алгоритмом и ограниченными внешними заменами.
Не делать платный или сетевой тест неявным условием запуска обычной тестовой команды.

## 28.4. Задание, ожидание, остановка и артефакт

Точки: `assistant/loop_tools.py`, `assistant/jobs.py`, существующие `aifa_wait`/`JobBoard`,
публикация результатов в Case, `assistant/ouro_view.py` и чтение состояния.

Сначала сквозные проверки:

- длительный `aifa_move` → `ЖДИ` → несколько `aifa_wait` → один итог и один опубликованный артефакт;
- повторная доставка принятого вызова и повторный опрос не увеличивают число сборов/LLM-вызовов;
- две одновременные доставки до первого ответа получают одно задание; изменённый payload с тем же
  `operation_id` отклоняется; тот же `ref` с изменёнными параметрами конфликтует, новый `ref`
  запускает новый сбор; составной ход переиспользует старую часть без подавления новых;
- чужой `job_id`, законченный ход, отмена, общий лимит и перезапуск не превращаются в успех;
- отмена до сбора, во время HTTP и во время Chromium ограничена сроком; после неё не возникает
  успешный артефакт; продолжающийся поток не выдаётся за остановленную работу;
- два владельца и два задания не смешивают кэши/счётчики перевода и результаты;
- чтение `DigestOutput` в другом времени и после обновления макрокэша побайтово сохраняет выпуск;
- длинный Markdown доступен целиком через явное продолжение/существующий файловый канал;
  `MoveOutcome` и `ouro_view` не превращают `partial`/ошибку в галочку полного выполнения.

Проверка завершения: настоящие API, очередь цикла, JobBoard, граф и Case с заменой только внешнего
сбора/модели/часов. Тест должен вызывать `aifa_wait`, а не ждать внутреннюю функцию напрямую.

## 28.5. Инструкции агента и приёмка

Точки: `skills/aifa-engine/SKILL.md`, `skills/aifa-planning/SKILL.md`,
`references/scenarios.md`, `external-data.md`, `moves.md`, `artifacts.md`, при необходимости
`skills/aifa-plan-author/SKILL.md`; контрактные снимки и реплеи.

Инструкции: дайджест без PDF открывает `market`; период переводится в часы; долгий вызов ждут
через `aifa_wait`; результат читают из Case. Расписание не создаётся. Отказы сети и неполнота
отражаются в ответе; макрочисла не дополняются вручную.

Приёмка:

1. Подставной агент и источники: запрос без отчёта → открытие → принятый план → сценарий →
   реальное ожидание задания → чтение → закрытие. Вариант с запретом сети — без единого запроса.
2. Прежние извлечение, расчёт и форма проходят те же проверки; документы и владельцы не смешаны.
3. F1/F2/F4/F8/F12/F13, тесты затронутых областей, навыков и полный `aifa/scripts/check.sh`.
   Исходные падения отделяются сравнением с базой; красные ворота не называются зелёными.
4. Независимое ревью в чистом контексте сверяет дифф, инварианты и Coding Rules.
5. Живой dev-smoke — только после сигнала владельца на выкатку, opt-in, с ограниченным каталогом
   и расходом. Не обращаться к prod и не перезапускать чужие прогоны.

## Риски и границы первой версии

| Риск | Как закрывается | Что не обещаем |
|---|---|---|
| Документные предположения в цикле | 28.1: восстановление, состояние и закрытие без паспорта | Выполнение отчётных сценариев в `market` |
| Старые кэши меняют выпуск | 28.3–28.4: снимок в Case, без `get_cached_digest` | Общий кэш готовых выпусков между владельцами |
| Источники возвращают короткую ленту | Предупреждение о глубине и статистика | Полный архив всех событий за неделю |
| Тихие отказы классификации | Проверка структуры и полноты ответа, явная ошибка | Фактчекинг каждой публикации |
| Сбор не останавливается вместе с await | Кооперативная отмена, сроки клиентов/браузера, запрет поздней публикации | Продолжение незавершённого сбора после рестарта |
| Сетевой эффект скрыт в атоме | Явный профиль, доверенный контекст и каталог адресов | Произвольные URL и пользовательский код с сетью |

Вне объёма: ежедневное расписание, новые источники, исправление всего старого приложения,
смешанный отчётно-рыночный цикл, автоматическая подмена финансового показателя новостными данными.
