# План реализации симбиоза AIFA и ouroboros

Пошаговый план по архитектуре `../architecture/` (ADR, контракты, проверки). Здесь — порядок
шагов, роли, цикл сессий и правила передачи контекста. Как писать код — `PRINCIPLES.md`, как
ревьюить — `REVIEW_GUIDE.md`, как тестировать продукт — `UI_TEST_GUIDE.md`, где что сделано и что
не получилось — `PROGRESS.md`.

---

## 1. Роли

| Роль | Агент | Что делает | Чего не делает |
|---|---|---|---|
| **Реализация** | Claude Code, Sonnet 5.5, усилие High | один шаг плана за сессию: тесты, затем код, коммиты, отчёт | не ревьюит свой код, не тестирует продукт глазами, не выходит за шаг |
| **Ревью** | Claude Code, Opus 5.5, усилие Medium, **чистый контекст** | вертикальное и горизонтальное ревью диффа шага; проверка связности тестов и контрактов; вердикт | не правит код продукта и тесты; не дописывает за реализацию |
| **Пользовательское тестирование** | Codex 5.6 Sol | проходит сценарии как аналитик через UI, сравнивает с опорными снимками, пишет дефекты | не читает код ради поиска причин, не правит код, не ходит в prod |

Сессия, написавшая код, не может его принять (Definition of Done ouroboros и правила AIFA).

## 2. Цикл одного шага

```text
  реализация NN  ──►  ревью NN  ──┬─ «можно дальше» / «с замечаниями» ──►  UI-тест NN  ──►  шаг NN+1
  (claude-impl)      (claude-review)│
                                    └─ «блокеры» ──► доработка NN (claude-impl/_FIX.md)
                                                         └──► повторное ревью NN (claude-review/_REREVIEW.md) ──► …
  UI-тест нашёл дефект уровня «блокер» ──► доработка NN ──► повторное ревью NN ──► повторный UI-тест NN
```

- **1 шаг = 1 сессия** у каждой роли. Доработка и повторное ревью — отдельные сессии того же шага.
- Следующий шаг начинается, только когда в `PROGRESS.md` у текущего: реализация — «готово», ревью —
  «можно дальше» (или «с замечаниями» без блокеров), UI-тест — «пройдено» (или «пройдено с
  дефектами» без блокеров).
- Замечания без блокеров не теряются: ревьюер и тестировщик пишут их в `PROGRESS.md` §4
  «Проблемы» с номером шага, который их закроет.

## 3. Передача контекста

| Сессия | Получает на вход |
|---|---|
| Реализация NN | `prompts/claude-impl/NN-*.md` (постановка, описание, образ результата, правила, проверки) + то, что в нём перечислено к прочтению |
| Ревью NN | **тот же** `prompts/claude-impl/NN-*.md` целиком (вход реализации), `PRINCIPLES.md`, `REVIEW_GUIDE.md`, отчёт реализации из `PROGRESS.md`, диапазон коммитов шага, `prompts/claude-review/NN-*.md` |
| UI-тест NN | `UI_TEST_GUIDE.md`, раздел «Образ целевого результата» из `prompts/claude-impl/NN-*.md`, вердикт ревью, `prompts/codex-uitest/NN-*.md`, каталог сценариев `uitest/SCENARIOS.md` |

Промпт ревью и UI-теста ссылается на промпт реализации, а не копирует его: так вход реализации и
вход проверяющих не расходятся. Ревьюер обязан прочитать его целиком **до** диффа.

## 6. Как запускать сессию

- Реализация: новая сессия Claude Code, модель Sonnet 5.5, усилие High; первым сообщением —
  содержимое `prompts/claude-impl/NN-*.md`.
- Ревью: **новая** сессия Claude Code, модель Opus 5.5, усилие Medium; первым сообщением —
  содержимое `prompts/claude-review/NN-*.md`.
- UI-тест: новая сессия Codex 5.6 Sol; первым сообщением — содержимое
  `prompts/codex-uitest/NN-*.md`.
- Доработка и повторное ревью — шаблоны `_FIX.md` и `_REREVIEW.md` с подставленным номером шага.

Пока `aifa/CLAUDE.md` не создан (шаг 02), правила симбиоза — часть Б
`../architecture/RULES.draft.md`.
