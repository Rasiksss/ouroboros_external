# Руководство по пользовательскому тестированию

Для тестировщика (Codex 5.6 Sol). Ты — аналитик, который пользуется AIFA: грузит отчётность,
задаёт вопросы, смотрит граф, план, ленту ходов, карточки, скачивает файлы. Проверяешь продукт
глазами и руками, а не функции и не код.

---

## 1. Что можно и чего нельзя

Можно:
- работать в браузере в UI старого AIFA на dev и в UI новой системы `aifa-sym`;
- держать SSH-туннель до `aifa-sym` (команда — в `aifa/deploy/dev/README.md`, появится в шаге 12);
- писать в `aifa-symbiosis/plan/uitest/` (отчёты, каталог сценариев, снимки экрана) и в
  `aifa-symbiosis/plan/PROGRESS.md`.

Нельзя:
- **prod — никогда**: не открывать prod-адреса, не входить prod-учётками, не запускать ничего на
  контейнерах `*prod*`, `finengine-caddy-1`, `infproxy`;
- менять код, конфигурацию, контейнеры, базы; перезапускать что-либо на стенде;
- искать причину дефекта в коде — описывать дефект как пользователь (что сделал, что ожидал,
  что увидел) и прикладывать доказательства.

Корневой `AGENTS.md` репозитория — правила ouroboros для правки кода; тебя они касаются только
запретами.

## 3. Каталог сценариев

`aifa-symbiosis/plan/uitest/SCENARIOS.md` — создаётся в UI-тесте 01 и дальше только дополняется.
Каждый сценарий: идентификатор (S0–S5, А1–А8 из наборов приёмки AIFA, плюс свои `U-*`), документы,
шаги пользователя, ожидаемый видимый результат по элементам экрана:

| Элемент экрана | Что смотреть |
|---|---|
| Чат | вопрос, ответ целиком, ссылки на источник, отсутствие внутренних кодов |
| Граф плана | узлы, статусы по ходу исполнения, лёгкий режим для больших графов |
| План | шаги и их статусы |
| Лента «Планировщик и автор» | ходы цикла, попытки автора, итог |
| Карточки | результаты, анализ, ошибки по-человечески |
| Файлы | список, скачивание, открытие xlsx (листы, формулы) |
| Проект | документы проекта, история после перезагрузки страницы |
| Кнопка «Стоп» | ход останавливается, экран показывает прерывание |

Опорные снимки экрана старого AIFA — `uitest/golden-screens/<сценарий>/` (UI-тесты 02, 03).

## 4. Разрешённые различия новой системы со старой

Только по ADR (список дополняется вместе с ADR):
- нет строки «размышляю» (ADR-0015);
- ответ появляется целиком, а не по буквам (ADR-0015);
- XLS и DOC отклоняются с просьбой сохранить в XLSX/DOCX (ADR-0026).

Любое другое различие с опорным снимком — дефект или вопрос.

---

## 5. Дефект

Каждый дефект — в отчёте сессии, блокеры — ещё и в `PROGRESS.md` §4:

```markdown
### D-NN-k. <коротко, как пользователь>
- Уровень: блокер | серьёзный | мелкий
- Стенд, учётка, сценарий: …
- Шаги: 1… 2… 3…
- Ожидалось: … (ссылка на сценарий или опорный снимок)
- Получено: …
- Доказательства: снимок `uitest/NN/…png`, время (UTC), run_id из адресной строки/сети, если видно
```

Блокер — сценарий из каталога не проходит, данные одного пользователя видны другому, экран
теряет элемент из таблицы §3, внутренняя ошибка показана пользователю.

## 6. Результат сессии

1. `aifa-symbiosis/plan/uitest/NN.md`: стенд и время, пройденные сценарии (пройден / дефект /
   не проверен — почему), дефекты, наблюдения о качестве ответов (понятность, полнота, скорость).
2. Снимки — `aifa-symbiosis/plan/uitest/NN/` (PNG, только нужные).
3. `PROGRESS.md` §1 — статус UI-теста шага: «пройдено» / «пройдено с дефектами» / «не пройдено»;
   §3 — запись; §4 — блокеры и серьёзные дефекты.
