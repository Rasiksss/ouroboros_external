## Вертикальное ревью
1. **`aifa_goal` успешный**: HTTP с токеном → привязка (прогон, владелец, чат, роль) → корень в
   `turn_gateway` → `parse_message` с **исходным сообщением прогона** → `execute_routed_goal(allow_dynamic=False)`
   → события в журнал **этого** хода → `ouro_view` → `ГОТОВО`.
2. **Сбой стандартного пути** → `DynamicRun` внутри (этап 2) → итог как `ГОТОВО`.
3. **Длинный**: 240 с → `ЖДИ` → `aifa_wait` → итог; отмена хода во время ожидания.
4. **Отказы**: без токена, чужой `run_id`, чужой владелец/чат, `aifa_goal` без аргумента из
   подзадачи → коды §3.0.
5. **Подцель**: `aifa_goal(goal)` разбирает переданный текст, итог — в `Case` хода, цикл не открыт.
На каждой границе — что видит ouroboros (текст) и что видит экран (события).

## Горизонтальное ревью
- Без `goal` цель берётся только из прогона; с `goal` — подцель, и она не подменяет исходную цель
  прогона и не открывает цикл (ADR-0040 п. 3).
- Ответы — только через `ouro_view` (C3.2); таблица результатов **переиспользует** `render_state`/`describe_execution`, а не пишет свою.
- Токен: сравнение за постоянное время; не логируется.
- Роуты тонкие; правила и задания — в доменных объектах.
- Задания: нет утечек фоновых задач; задание чужого хода недоступно; перезапуск процесса — что
  с незавершёнными заданиями (описано ли).
- Ограничение размера ответа (12 000) соблюдается на большой таблице.
