## Постановка задачи
Сделать инструменты опорной записи: формат записи хода, записывающий клиент, который проводит ход
через API службы как пользователь, нормализатор и сравнение двух записей.

## Описание
- `aifa/tests/golden/`:
  - **формат записи** одного сценария: метаданные (сценарий, стенд, коммит/сборка, время, документы
    и их `sha256`), реплики пользователя по порядку, полный поток событий SSE каждого хода, текст
    финального ответа, ссылки на файлы-результаты (имя, размер, `sha256`), снимок `Case`/артефактов,
    если доступен через API (иначе — пометка «нет»);
  - **записывающий клиент** (CLI): вход по учётке → проект → загрузка документов → ходы
    (`POST /chat/turns`, чтение `events` до `done`/`error`) → скачивание файлов → запись;
    адрес и учётка — переменными окружения, не в git; таймауты под длинные ходы;
  - **нормализатор**: убирает `run_id`, время, длительности, стоимость, токены, идентификаторы
    узлов/артефактов (замена на стабильные порядковые метки), порядок независимых событий — по
    правилам, которые ты выведешь из `use-chat-run.ts` (что экрану важен порядок, а что нет);
    список правил — в коде, у каждого — «почему»;
  - **сравнение**: две нормализованные записи → равны / список различий человекочитаемо
    (тип события, поле, было/стало) + «разрешённые различия» с номером ADR (`thinking`, порядок
    `text_delta`, XLS/DOC).
- **Проверка устойчивости** на старом dev AIFA: один короткий сценарий (S0 или проще) записать
  дважды; после нормализации — равны. Нестабильные поля, которые нормализатор не снял, — правило
  или запись в §4.
- Записи этого шага — служебные (проверка инструмента), в `golden/_selftest/`.

## Образ целевого результата
- CLI записывает ход старого AIFA на dev и сравнивает две записи; две записи одного сценария
  равны после нормализации.
- Нормализатор и сравнение покрыты тестами на синтетических потоках (порядок, удаление полей,
  разрешённые различия).
