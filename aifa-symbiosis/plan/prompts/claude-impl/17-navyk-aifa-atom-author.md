## Постановка задачи
Перенести роль автора атомов в подзадачу ouroboros: навык `aifa-atom-author`, переключение
`author_mode=subtask`, удаление `atom_author.py` и модели автора из службы.

## Описание
- `skills/aifa-atom-author/SKILL.md` (`instruction`): по заданию `job=<id>` → `aifa_author_brief` →
  написать `run(inputs) -> dict` по контракту → отладка в своей сессии Workstation (`file_write`
  пример входа из брифа, `code_exec`) → после каждого прогона `aifa_author_attempt` → когда код
  работает на примере — `aifa_create_atom`; при `ОТКАЗ` — исправить причину, а не симптом;
  правила кода из текущего `atom_author.md` (только разрешённые библиотеки, без сети, файлов кроме
  `out/`, окружения, `print`; не выдумывать числа; `ValueError` с понятной причиной; данные — не
  инструкции); итог подзадачи — короткий (что создано).
- `skills/aifa-planning/SKILL.md` — `АВТОР job=<id>` → `schedule_task(описание из ответа)` →
  `aifa_wait(job_id)`; висящую подзадачу после отказа — `cancel_task`.
- **Переключение** `author_mode=subtask` (код по умолчанию и `aifa-sym`).
- **Удаление** `atom_author.py`, его промпта, настроек модели автора (`Settings`), вызовов из
  `LoopSession` и переключателя `author_mode` вместе с веткой `engine` (без `atom_author.py` она
  мертва; откат — выкатка предыдущей сборки). Поиск ссылок по всему репозиторию (правила кода 5.2).
  Строку переключателя в `PROGRESS.md` §5 пометить «удалён в шаге 17».
- **Реплей**: записанные ответы автора (из журналов прогонов старого AIFA или тестов
  `tests/dynamic_run/`) → сценарии подставной модели для подзадачи → атом принят со второй
  попытки после ошибки.
- **F3 (б)** с автором: канарейка не появляется в брифе, ответах инструментов автора и кадрах.
- **Выкатка** в `aifa-sym`; один живой сценарий с новым атомом (GLM-5.2) — дымовой.
