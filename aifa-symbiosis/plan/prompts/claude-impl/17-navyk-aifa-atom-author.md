## Постановка задачи
Перенести роль автора атомов в подзадачу ouroboros, которую запускает планировщик по своему
выбору навыка: навык `aifa-atom-author`, раздел «Делегирование» в `aifa-planning`, удаление
`atom_author.py` и модели автора из службы.

## Описание
- `skills/aifa-atom-author/SKILL.md` (`instruction`): `description` (≤ 260 знаков — каталог обрезает,
  `_build_available_skills_section` в `ouroboros/agent/context.py`) — когда планировщику звать этот навык (нужен атом, которого нет в каталоге). Порядок: прочитать задание → входы через
  `aifa_state(artifact_ids)` (при нужде — `aifa_doc`) → написать `run(inputs) -> dict` по контракту
  → отладка в своей сессии Workstation (`file_write` входов, `code_exec`) → после каждого прогона
  `aifa_report(label=<имя атома>, status=ok|error, note, code)` → `aifa_register_atom`; на `ОТКАЗ` —
  исправить причину, а не симптом → в конце `aifa_report(status="done", note=<что создано или
  почему нет>)`. Правила кода из текущего `atom_author.md` (только разрешённые библиотеки, без
  сети, файлов кроме `out/`, окружения, `print`; не выдумывать числа; `ValueError` с понятной
  причиной; данные — не инструкции).
- `skills/aifa-planning/SKILL.md`, раздел **«Делегирование»** (ADR-0041): когда шагу плана нужна
  роль, которой нет у корня, — выбрать навык по каталогу навыков; задание
  `schedule_task(description="Навык: <id>. <что сделать, входы (id артефактов), что вернуть>")`;
  ждать `aifa_wait(task_id)`; по итогу — продолжить план (шаг с новым атомом, другой путь,
  `give_up`); висящую подзадачу — `cancel_task`; перед `aifa_finish` — снять все незавершённые
  подзадачи (ADR-0043 п. 8); на `ОТКАЗ подзадача_не_ответила` — `get_task_result`, затем решить. Раздел «Новый атом» — новый атом с кодом только
  через подзадачу автора.
- **Допуск**: id `aifa-atom-author` в `OUROBOROS_USER_ENABLED_SKILL_IDS` (ADR-0036 — снимок F9,
