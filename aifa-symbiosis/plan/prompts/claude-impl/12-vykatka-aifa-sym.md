## Описание
- **Предусловия**: сигнал «выкатывай» (§2).
- **Выкатка** по `aifa/deploy/dev/README.md`: `docker ps` до; доставка `git bundle`; сборка
  `finengine`, `frontend` (с `BUILD_ID` = коммит), пересоздание `ouroboros` (новые навыки и
  `OUROBOROS_ENABLED_TOOLS`); подъём с профилем `app`; база службы — миграции; `docker ps` prod
  до/после.
- **Доступ пользователей**: фронтенд `aifa-sym` публикуется только на `127.0.0.1:<порт>`; доступ —
  SSH-туннель; команда туннеля — в `README.md`. В `finengine-caddy-1` ничего не добавлять.
- **Учётки**: две тестовые учётки `qa-a`, `qa-b` в базе службы `aifa-sym` (способ — штатный для
  AIFA; пароли — на сервере в файле с правами 600, передаются владельцу, не в git).
- **Дымовые** (скрипты `aifa/deploy/dev/smoke/`, дополнить): `/health` службы, `/build-id` фронтенда,
  вход `qa-a`, ход «привет» через UI-ручки (API) доходит до ouroboros и обратно.
- **Проверка S0–S5**: ходы наборов через API `aifa-sym` (учётка `qa-a`; реплики и документы — по
  `34-status.md`, части 12 и 15) → таблица: сценарий × «Ожидание» × факт × вердикт (пройден /
  частично / **дефект**). Дефект, который чинится в пределах шага (ошибка конфигурации, выкатки, явная ошибка
  кода шагов 08–11 с тестом), — чинить отдельным коммитом с тестом; остальное — §4 с номером
  шага-закрывателя.
- В `aifa/deploy/dev/README.md` — что развёрнуто (коммит, сборка), команда туннеля, где лежат
  пароли учёток, известные ограничения.

- Ходы S0–S5 через `aifa-sym` доходят до ожидаемого итога (`34-status.md`); дымовые скрипты
