## Постановка задачи
Дать любой подзадаче ouroboros общие операции службы — регистрацию нового атома, отчёт в ленту
экрана и ожидание подзадачи планировщиком с конечным сроком — так, чтобы служба не знала, какой
навык у подзадачи (ADR-0041, ADR-0043). Включить подзадачи в конфигурации dev. Автор пока остаётся в
службе (`atom_author.py`) и сдаёт код тем же путём регистрации; поведение пользователя не меняется.

## Описание
- **Конфигурация** (ADR-0043 п. 1, ADR-0044 п. 3): убрать `schedule_task` из
  `OUROBOROS_DISABLED_TOOLS` в `ouroboros.env.example` и снимке F9 (та же короткая ADR шага — F13),
  при выкатке — в `ouroboros.env` на dev; живой контур: подзадача стартует (дымовая).
  `send_user_message` остаётся выключенным.
- **`atom_intake`** — одно место проверки и регистрации атома: имя `eph.<snake_case>`, контракт
  (правила `check_request`), входы `requires` есть в `Case`, один прогон в разовой комнате на
  настоящих входах, результат по `output_schema`, регистрация `eph.<snake_case>@<версия>` (версия =
  хэш контракта и кода), исходник в `Case`; ≤ 3 неудачных регистрации одного имени **за ход цикла**
  (как нынешние 3 попытки автора на запись — проверь тестом, что предел автора не изменился);
  лимит новых атомов `RunLimits`; сбой станции попытку не тратит; новая регистрация имени снимает
  его сигнатуры тупика (`_rewrites_ephemeral` учитывает и `atom_intake`). `atom_author.py`
  переводится на `atom_intake` — без второй копии проверки.
- **Счётчик попыток** (ADR-0044 п. 1): один на пару (ход цикла, имя атома) для `aifa_report` и
  `aifa_register_atom`, номера — как нынешние 1..3 на запись, увеличение атомарно; `move` события — последний начатый ход цикла; эмиттер — тот же, что
  `_report_author_attempt`.
- **`aifa_register_atom`** — вход в `atom_intake` из любой задачи хода; изменяющий вызов в очереди
  хода (§3.0), «240 с, затем фон».
- **`aifa_report`** — `ok`/`error`: событие `author_attempt`; `done`: только из подзадачи (из корня
  — `не_та_роль`), без события, завершает её ожидание; ≤ 20 отчётов на задачу ouroboros.
- **`subtask_waits`** и **`aifa_wait(task_id)`**: подзадача хода запоминается по первому её вызову
  или кадру; завершена по первому из: кадр итога из `turn_gateway` с
  `transport.source_message_id == run_id` (кадр «⚠️ Error during processing…» — итог «подзадача
  упала»), `aifa_report(status="done")`; срок — от первого `aifa_wait` по ней (`Settings`, 600 с),
  не дольше остатка времени цикла: `ОТКАЗ подзадача_не_ответила` / `ЛИМИТ` (вне цикла — только
  срок, ADR-0044 п. 5); каждое `ЖДИ` — с
  подсказкой `get_task_result`/`cancel_task`.
- **`aifa_finish`**: `ПРИНЯТО` перечисляет подзадачи хода, не завершённые по данным
  `subtask_waits` (ADR-0043 п. 8).
- **Привязка** (§3.0): роли ADR-0043 п. 2; вызовы `LoopSession` хода — через очередь шага 13.
- **`aifa_move`**: атом с кодом в `new_atoms` по-прежнему уходит в `atom_author.py` (до шага 17,
  ADR-0029).
- **Навык-фикстура** для C4.7 — `aifa/tests/contract/skills/<имя>/SKILL.md`, подключается только в
  профиле `contract` (каталог навыков контейнера и `OUROBOROS_USER_ENABLED_SKILL_IDS` — окружением
  профиля); способ подключения записать в отчёт и `aifa/tests/contract/README.md`.
- **Плагин**: регистрация `aifa_register_atom`, `aifa_report`; `task_id` в `aifa_wait`; снимок
  схем по ADR-0042 (+ короткая ADR в диапазоне шага — F13, ADR-0043 «Следствия»); бюджет F4.

## Образ целевого результата
- Регрессия: поведение как после шага 15; атомы автора службы регистрируются через `atom_intake`.
- Контрактный тест на настоящем ouroboros с подставной моделью: корень вызывает
  `schedule_task("Навык: <фикстурный навык>. …")` → `aifa_wait(task_id)` → подзадача:
  `aifa_state` → `aifa_report error` → `aifa_register_atom` (первая — `ОТКАЗ`, вторая — `ГОТОВО`) →
  `aifa_report done` → корень получает итог → `aifa_move` с `eph`-атомом → `aifa_finish`.
  C4.1, C4.3–C4.9 зелёные; C4.2 (та же сессия и нет сети) — живой, пропускаемый.

## Границы
Не делать: навык `aifa-atom-author` и раздел «Делегирование» `aifa-planning` (шаг 17); удалять
`atom_author.py` и атом с кодом в `new_atoms` (шаг 17); код, зависящий от имени навыка подзадачи.
Разрешено (ADR-0043 п. 6): правка `_rewrites_ephemeral` под `atom_intake`. Не вводить запрет
подзадач подзадачам по `task_depth` (P46) — это решение владельца.
