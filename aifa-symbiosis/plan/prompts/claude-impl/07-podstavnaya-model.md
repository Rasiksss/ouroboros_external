## Описание
- **Предусловие**: ouroboros позволяет окружением направить модель агента на произвольный
  OpenAI-совместимый адрес. Нельзя без правки ouroboros — стоп, запись в §4 с вариантами.
- `aifa/tests/stub_model/`:
  - HTTP-сервер (`/v1/chat/completions`, при необходимости `/v1/models`), отвечающий по
    **сценарию** — файл YAML/JSON со списком шагов: условие (последнее сообщение пользователя
    содержит …; последний результат инструмента начинается с кода …; номер круга) → ответ (текст
    или вызов инструмента с аргументами); нет совпадения — ответ-ошибка с понятным текстом
    (тест падает, а не зависает);
  - поддержка того, что шлёт ouroboros: потоковый и непотоковый режимы — какой нужен, определи по
    его клиенту; вызовы инструментов в формате OpenAI; лёгкая модель (сжатие, проверки) — тем же
    сервером, отдельными правилами или универсальным ответом;
  - журнал запросов (для проверок «модель увидела / не увидела»).
- `aifa/deploy/dev/compose.contract.yml` (или профиль `contract`): `ouroboros` + его PostgreSQL + S3
  + `stub-model`; без Workstation (тесты с Workstation — живые); поднимается локально.
- **Тестовый клиент WS** для этого шага — в `aifa/tests/contract/` (минимальный; настоящий
  `ouro_client` службы появится в шаге 08 и заменит его в тестах).
- **Дымовой контрактный тест**: сценарий «привет» → ouroboros с подставной моделью отвечает
  заданным текстом; кадры: эхо с `client_message_id`, финальный ответ с `transport.source_message_id`;
  повтор даёт тот же результат. Это первый тест, проходящий через границу служба ↔ ouroboros.

## Образ целевого результата
- `docker compose … --profile contract up` локально поднимает ouroboros с подставной моделью.
- `pytest aifa/tests/contract -k smoke` зелёный и детерминированный.
- Формат сценариев описан в `aifa/tests/stub_model/README.md` с примером.
