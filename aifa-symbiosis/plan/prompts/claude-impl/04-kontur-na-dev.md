## Описание
- **Предусловия**: сигнал «выкатывай», О2, согласованный список чистки — в `PROGRESS.md` §2.
  Нет — стоп с записью.
- **До любых изменений**: `docker ps -a --format '{{.Names}} {{.Status}}'`, `df -h /`, `free -m` →
  сохранить на сервере `~/aifa-sym-before-<дата>.txt` и в отчёт. Каждая `docker`-команда — с
  явным `-p aifa-sym` или именем без `prod`.
- **Чистка диска** — строго по согласованному списку; ничего сверх. После — `df -h /`.
- **Доставка кода** без push: `git bundle` ветки симбиоза → `scp` → клон в `/home/rasul/aifa-sym`
  (каталог по согласованию; не `/opt/finagent*`). Секреты — файлы `.env` на сервере, вне git,
  права 600; ключ шифрования ouroboros — сгенерировать на сервере.
- **Сборка** образов `ouroboros`, `workstation` на сервере (с учётом диска), подъём без профиля
  `app`.
- **Дымовые проверки**, оформленные скриптами в `aifa/deploy/dev/smoke/` (чтобы их повторял
  шаг 12 и далее):
  1. `/ready` ouroboros — 200 (через `127.0.0.1`);
  2. WS-рукопожатие из внутренней сети (одноразовый контейнер в сети `aifa-sym`) с
     `X-Ouroboros-Owner-Id: smoke`, `X-Ouroboros-Chat-Id: smoke-1`; реплика «привет» → ответ модели
     (живой GLM-5.2); без `X-Ouroboros-Owner-Id` — отказ рукопожатия;
  3. ouroboros выполняет код в Workstation контура (реплика с просьбой выполнить
     `print(2+2)` через `code_exec`) — в логе ouroboros вызов `code_exec` и ответ;
  4. C5.2 живой: разовая комната по протоколу `sealed_room` (из образа `finengine` одноразовым
     контейнером или скриптом `httpx`): импорты `numpy`, `pandas`, `openpyxl`, `pptx`, `docx`;
     сокет не открывается; переменных окружения службы нет.
- **Проверки 0.7** (результат — в отчёт и, при расхождении с ADR-0027, **предложенная** ADR):
  - P2: как расширение получает настройки — прочитай `ouroboros/skills/extensions/loader.py`
    (`get_settings`, источник `settings_reader`) и проверь на живом экземпляре (минимальный
    временный навык не создаём — достаточно кода и `docs/SETTINGS.md`; если нельзя решить без
    эксперимента — запиши);
  - P3: список инструментов и навыков живого экземпляра (через `list_available_tools`/`list_skills`
    — реплика агенту или Python внутри контейнера) → окончательные `OUROBOROS_DISABLED_TOOLS`,
    `OUROBOROS_DISABLED_SKILLS` в `ouroboros.env.example` и снимок F9;
  - P5: память контейнеров под нагрузкой дымовых проверок (`docker stats --no-stream`).
- **После**: `docker ps` prod-контейнеров до/после совпадает (имена, статус, время старта);
  старый AIFA (`finengine-*` dev) отвечает `/health`.
- `aifa/deploy/dev/README.md` — точный порядок выкатки, которым ты пользовался, и откат
  (`docker compose -p aifa-sym down`, тома не удалять без команды владельца).

## Образ целевого результата
- `aifa-sym` работает на dev: `/ready` зелёный, агент отвечает по WS с доверенными заголовками,
  код исполняется в Workstation контура, разовая комната работает.
- prod и старый AIFA не затронуты — доказано сравнением.
- P2, P3, P5 закрыты или переведены в предложенные ADR / проблемы с конкретным следующим шагом.
