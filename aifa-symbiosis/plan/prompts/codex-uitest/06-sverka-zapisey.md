## Что тестируешь
Опорная запись станет эталоном для всех следующих этапов: она должна описывать то, что реально
видит пользователь.
- Для каждого из S0–S5, А1–А8 открой в старом UI записанный ход (проект записи) и сравни с опорным
  снимком: всё ли видимое на снимке отражено в записи (по `golden/README.md`: какие события, какие
  файлы, какой ответ). Пропуск — дефект записи.
- «Известные сбои эталона» из README — подтверди глазами, что на старом AIFA так и есть.
- Разброс: если у пары записей одного сценария разные ответы — какой из них видит пользователь и
  оба ли приемлемы как продукт.
