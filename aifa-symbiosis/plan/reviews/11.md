## Вертикальное ревью

### 1. Документ: загрузка → каталог → распознавание → ход → выдача → удаление
- Ручка `/documents/upload` (`api/main.py:619–720`): XLS/DOC отклоняются до всего остального
  (`legacy_office_refusal`, 400, текст ADR-0026); ворота PDF смотрят байты в памяти; затем
  `catalog().upload` (`ouro_files.py:93`): multipart `file` без типа части (обосновано живым каталогом),
  заголовок владельца — `ouro_client.owner_headers` (F12), владелец — `user.id`. 201 → `StoredFile`;
  400/413/415/422 → `FileRefused` с русским текстом; 5xx/429/сеть → `OuroUnavailable` → 503 «Повторите…».
  Документ регистрируется только после ответа каталога — «полузагруженного» документа нет (тест
  `test_a_catalog_that_is_down_stops_the_upload_and_registers_nothing`). Пара `catalog_file_id` + `sha256`
  — в `DocumentMeta` (JSON-колонка, без DDL; откат описан). Соответствует §6.
- Распознавание (`main.py:519`, `store/originals.py`): байты из каталога во временный каталог, уборка
  в `finally`; при недоступном каталоге — В3.
- Ход с документом: настоящий ouroboros, `aifa_goal`, числа из конвейера (`test_files_end_to_end.py:115`).
- Выдача `/documents/{id}/file` — `StreamingResponse` из `GET /api/files/{id}/content` с закрытием потока
  в `BackgroundTask`; чтение у владельца документа (`doc.owner_id`), а не у зрителя — верно для общих
  документов.
- Удаление: каталог первым, затем запись; каталог не ответил — 503 и документ остаётся (тест есть).

## Замечания

### Блокеры
**Б1. История чата внутри папки читается не из того чата, в который писал ход.**
`api/main.py:1542` — ход: `chat_id = chat_of(request.project_id, …)`, а фронтенд для чата в папке шлёт
`project_id = p.folder_id ?? p.id` (`web/src/components/workspace/use-chat-run.ts:1020`). История:
`_chat_of_session` (`main.py:2709–2714`) возвращает `project["id"]` карточки чата — то есть `p.id`, не
папку. Итог: для любого чата в папке `GET /chat/history` спрашивает у ouroboros пустой чат → 404;
восстановление ленты и догон позднего ответа (`use-chat-run.ts:375–460`, `late-answer.ts`) для таких чатов
перестают работать (прежде работали: история шла по сессии). Вторая половина: фильтр
`turn_messages` (`assistant/history.py:97`) берёт **любую** реплику с uuid-видом `client_message_id`, а
`CONTRACTS.md` §2.6 — «с `client_message_id`, равным `run_id` **своих ходов**»; несколько чатов одной папки
пишут в один чат ouroboros (`folder_id`), поэтому простое «спросить папку» смешает их переписку.
Воспроизведение: в обвязке `test_chat_history_from_ouroboros.py` положить в `dialogs` карточку
`{"id": "chat-a", "folder_id": "folder-1", "session_id": SESSION}` — запрос уходит с
`x-ouroboros-chat-id: chat-a`, ход писал в `folder-1` (проверено временным тестом: `'chat-a' == 'folder-1'`
ложно). Тест на чат в папке отсутствует.
Как закрыть (выбор — доработки): чат истории вычислять тем же правилом, что ход (`folder_id ?? id` из
карточки), а ходы сессии брать из журнала прогонов службы (`run_orchestrator`, `meta.session_id`) и
фильтровать по этим `run_id` — ровно как в §2.6. Тест: два чата одной папки, история каждого — только
свои ходы.

### Важно
**В1. Новая ошибка mypy службы (433 против 432).** `skills/spec/dynamic_run.py:776–780`: `"trace_id"`
добавлен в `observer: dict[str, object]`, распаковка `**observer` в `AtomAuthor.write` → `arg-type`
(«Argument 6 … expected "str"»). Внесено доработкой `54d880c`; её запись про mypy не говорит, §3 по-прежнему
утверждает «432 (как было)». Нарушение храповика долга. Исправление — передать `trace_id` аргументом либо
типизировать `observer` (`TypedDict`).

**В2. Финал корня выбирается по порядку, а не по `task_id` корня; против принятого плана ADR-0046.**
`assistant/history.py:96–112`: финал — «первая непрогрессная запись ассистента с `task_id`». Промпт шага и
`CONTRACTS.md` §2.6 называют `task_id`, равный корню (`run.root_task_id`). Отступление описано только в
«Что и почему», а не в §4 (`PRINCIPLES.md` §А.2). Правило держится на ADR-0046 «подзадача стартует после
корня», а владелец уже принял «D до шага 16, **затем B**» — при B подзадача запускается во время корня и её
итог (тот же `client_message_id`, свой `task_id`) может прийти раньше финала корня и стать «ответом» хода
в истории. Живого C1.3 с настоящей подзадачей нет (`test_files_end_to_end.py:165–191` проверяет только
набор ролей), хотя сценарий настоящей подзадачи в профиле `contract` уже есть (`test_c2_4_…`).
Как закрыть: записать в §4 с закрывателем шаг 16; корень хода хранить вместе с прогоном (журнал прогона
переживает 6 часов кэша `TurnRecord`) и фильтровать по нему; живой C1.3 на сценарии C2.4.

**В3. Распознавание при недоступном каталоге — молчаливый вечный «в обработке».**
`api/main.py:519`: `document_original` в фоне бросает `OuroUnavailable`/`FileNotFoundError`, общий
`except Exception` (`main.py:609–611`) только пишет в журнал; документ остаётся без текста, пользователь
узнаёт об этом лишь ошибкой «still processing» в `/extract/stream`, повтора нет. Новый источник отказа на
задетой границе без теста и без понятного текста пользователю.
