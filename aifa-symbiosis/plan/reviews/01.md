## 5. Замечания по уровням

### Важно

**В1. 12 тестов службы молча перешли из «прошёл» в «пропущен».**
`aifa/finengine/tests/test_underwriter_spec_matches_the_code.py:35,38` — `SPEC = REPO / "docs" /
"UNDERWRITER_RISK_SKILL.md"`, `skipif(not SPEC.is_file(), reason="спека не заведена")`. Файл есть в
`f4a12fc6`, но не в списке переноса (`docs/` переносится выборочно) и не в ADR-0032. Сравнение базовых
линий шло только по падениям; рост пропусков 154 → 165 в записи не объяснён (12 новых пропусков, одним
пропуском меньше в другом месте). Проверка «тесты дают ту же картину, что AIFA» не выполнена для этих
12 тестов: сверка спеки андеррайтера с кодом больше не идёт.
Воспроизведение: `pytest tests/test_underwriter_spec_matches_the_code.py -rs` в `aifa/finengine` —
12 skipped; на реплике эталона (`docs/` на месте) — 12 passed.
Закрытие: перенести `docs/UNDERWRITER_RISK_SKILL.md` в `aifa/finengine/docs/` (тот же путь от
`REPO`) отдельным структурным коммитом — выходит за список шага и ADR-0032, нужно согласие
владельца → P14 (шаг 02). Заодно сверять базовую линию и по списку пропусков.

**В2. Без `deploy/` меняется поведение самой службы, а не только тестов.**
P13 описывает 120 падений как «тесты читают `deploy/…`», но часть падений — от кода продукта:
- `aifa/finengine/src/finengine/llm/tools.py:2025-2036` — каталог инструментов AUA ищется в
  `parents[3]/deploy/tools_whitelist.yaml`; без файла — `return None`, то есть **все
  зарегистрированные инструменты открыты** (fail-open, УЭК-АУА-7/13 в докстроке);
- `aifa/finengine/src/finengine/net/ru_gov_tls.py:38` — сертификаты Минцифры ищутся в
  `parents[3]/deploy/certs`; без них `ru_gov_ssl_context()` → `None`, Росстат недоступен. Это и ловят
  `tests/test_ru_gov_trust_is_scoped.py::test_state_sites_get_the_extra_trust[*]`,
  `test_regulator_sources_point_at_regulators.py::test_scoped_trust_actually_reaches_the_collector`;
- `src/finengine/demo/` — снимки `deploy/demo/`.
Сейчас это касается только запуска службы из `aifa/finengine` вне образа (шаг его не запускает). Но
для шага 03 есть ловушка: в образе `parents[3]` = `/app`, AIFA кладёт файлы в `/app/deploy/…`
(`Dockerfile.backend`: `COPY deploy/tools_whitelist.yaml`, `COPY deploy/certs/`), а по ADR-0020
контекст образа `finengine` — `aifa/finengine`, тогда как `deploy/` по ADR-0019 — `aifa/deploy/dev/`,
вне контекста. Забытый `COPY` даст тихо открытый каталог инструментов. → P15 (шаг 03: способ доставки
`tools_whitelist.yaml`/`certs/` в `/app/deploy/` и тест, что в образе каталог не пустой).

**В3. Записанная команда базовой линии её не воспроизводит.**
`PROGRESS.md` (запись 01): «все прогоны — `pytest tests -q`». На перенесённом дереве эта команда
прерывается на сборке: `tests/test_plugin_parity.py:62-64` импортирует `gen_fe_tools` из
`deploy/gateway-plugins` → `Interrupted: 1 error during collection`, ни одного теста. Числа
212/18/4456 получаются только с `--continue-on-collection-errors`. Шаг 02 строит ворота на этой
базовой линии → P16 (шаг 02: записать точную команду; известные ошибки сборки — в список известных
красных).

### Замечания

**З1. Версии зависимостей.** Мажорных расхождений нет. Образ AIFA ставит зависимости **без замка**
(`deploy/Dockerfile.backend`: `uv pip install --system -r` из `>=` в `pyproject.toml`), поэтому версии
на стенде нигде не записаны. Против локального окружения AIFA (`Krab_ext/AIFA-CLAW/.venv`, 23.09):
`pydantic` 2.12.5 = 2.12.5, `httpx` 0.28.1 =, `mcp` 1.30.0 =, `redis` 8.1.0 =; `fastapi` 0.141.1 →
0.143.0, `starlette` 1.6.0 → 1.8.0, `openai` 3.11.0 → 3.31.0, `anthropic` 1.4.0 → 1.13.0,
**`sqlalchemy` 2.0.52 → 2.1.4** (минорная, но 2.1 убирает устаревшее), `uvicorn` 0.52.4 → 0.54.0,
`pandas` 3.0.5 → 3.0.6. Эталон и перенос ревьюер и реализация гоняли в одном окружении нового
замка — дрейф зависимостей базовой линией не ловится. Предложение для шага 03/04: снять
`pip freeze` с `finengine-backend-1` (только чтение) и сверить с замком.

**З2. Адреса инфраструктуры уйдут на GitHub при push.** Не секреты, но: публичные IP
`188.72.106.8:8896` (`src/finengine/skills/aifa_baseline/idp_ocr_client.py:3` и копия в
`benchmarks/vendor/…`), `144.31.112.12:8888` (`tests/test_infproxy_second_upstream.py:116`), пути
`/home/rasul/…` бэкапов в `docs/build-plan/34-status.md:46,1832`, `tests/dynamic_run/live/runs/…/report.md:96`.
Решение — владельцу до первого push ветки.

**З3. ADR-0032 оформлена реализацией сразу со статусом «принято (владелец)».** По `PRINCIPLES.md`
А.3 агент предлагает, принимает владелец. Основание («Реализуй вариант а») записано в R4, так что по
существу верно; на будущее — статус «предложено» и смена статуса отдельной строкой владельца.

**З4.** `core.autocrlf=true` в конфиге машины подтверждён; рабочее дерево сейчас = `HEAD`, но первая
же правка CRLF-фикстуры или `*.sh` будет нормализована — уже записано как P10, срочность растёт к
шагу 03 (`*.sh` в образах).
