## Вертикальное ревью
1. **Реплей решений.** Сценарий подставной модели (`replay_support.scenario_of`): `skill_read` `SKILL.md` →
   `skill_read references/moves.md` → `aifa_goal` → `aifa_move`… → `aifa_finish` → текст. Путь: ouroboros
   (`skill_read` настоящий, инструменты `ext_13_r_aifa-engine_*`) → плагин → `tool_api` службы → `MoveTool` /
   `FinishTool` (`loop_tools.py:64-123`) → `decision_from_data` → `LoopSession.check/move/finish` → фикстурный

   `ОТКАЗ`, ход потрачен, следующий проходит) покрыт. Перевод «решение → аргументы» сверен с `parse_decision` на 4
   живых записях и 4 наборах; аргументы — только из снимка F4. Прогнано, зелёное (кроме нестабильности В3).
   Ограничение (P101): подставная модель вызывает записанное независимо от текста навыка — реплей держит
   связность и равенство ведущих, а не следование навыку; `skill_read` в самом реплее не проверяется (проверяет
   отдельный `test_ouroboros_reads_the_skill_and_every_reference_it_names`).
2. **Документ и артефакты (ADR-0040 п. 2).** `SKILL.md:66-73` велит `aifa_doc` без аргументов → `query` → `pages`,

   `test_a_long_document_is_read_by_search_and_pages_and_never_whole`: 60 страниц, список → поиск (стр. 41) →

4. **Отказные пути навыка.** `ЛИМИТ` → только `aifa_finish` (`loop_tools.py:71-73`, `:112-120`), `цикл_закрыт`,

## Замечания

### Блокеры
Нет.

### Важно
- **В1. `ГОТОВО` в правиле 3 относится ко всем инструментам и велит закончить без `aifa_finish`.**
  `skills/aifa-planning/SKILL.md:17` («Первая строка ответа инструмента — код… Действуй по коду») и `:22-23`
  («`ГОТОВО` — … Цикла нет: `aifa_move` и `aifa_finish` не вызывай, отвечай пользователю сразу»). Но `ГОТОВО` —
  первая строка и у `aifa_move` (`aifa/finengine/src/finengine/assistant/ouro_view.py:194-195`), и у `aifa_doc`
  (`:223`, `:228`), и у `aifa_wait` по заданию хода. Буквально после первого успешного хода или чтения документа
  навык велит ответить пользователю, не закрыв цикл; закрытия по концу хода нет — не будет финального
  `dynamic_move`, файлы `deliverables` не опубликуются. Раздел «Цикл» (`SKILL.md:54`) говорит обратное, модель
  выбирает между ними. Тест `skills/aifa-engine/tests/test_planning_text.py:51-56` закрепляет формулировку.
  Живой GLM-5.2 прошёл верно — одна выборка. Как воспроизвести: прочитать правило 3 применительно к ответу
  `aifa_move`. Исправление: «ответ `aifa_goal` `ГОТОВО`…» и в «Цикле» — «`ГОТОВО` у `aifa_move`/`aifa_doc` — не
  конец: цикл закрывает только `aifa_finish`».
- **В2. Перенос промпта неполон, и это не записано.** Не найдены в навыке (поиск по `skills/aifa-planning`) правила
  `dynamic_run_planner.md`: `:180` «строка с «—» в первом столбце (форма роли) не цитируется — цитируй
  показатели»; `:182` «файл по плану собран — сразу `finalize`, без новых расчётов»; `:184` «в `evidence_ids`
  достаточно нескольких ключевых показателей»; `:195` «укажи id находок или скачанной страницы в `evidence_ids`»
  (внешние данные; `SKILL.md:90-92` его потерял). Три из четырёх — про `evidence_ids`, то есть про замер
  ADR-0040 п. 1: «—» в `evidence_ids` журнал запишет как несуществующую ссылку, ответы на внешних данных без id
  находок будут выглядеть «без опоры на `Case`» — доля исказится. Запись §3 («finalize (→ «Завершение»)»
  перенесён) и тест полноты `test_planning_text.py:105-127` этого не видят.
- **В3. Реплей нестабилен.** `aifa/tests/contract/test_planning_replay.py:156` (`cycle_of(actual) ==
  cycle_of(expected)`) упал 1 раз из 12 прогонов (полный `aifa/tests` при параллельной нагрузке): index 26,
  `node_run` `verify.bounds`, расходятся `produced_evidence_ids`/метки. Вероятная причина: нормализатор
  упорядочивает независимые `node_run` только по (атом, версия) (`aifa/tests/golden/golden_normalize.py:264-273`),
  и два `verify.bounds` одного хода, завершившиеся в разном порядке, получают разные метки `<id:N>`. Ворота
  `aifa/scripts/check.sh` будут изредка ложнокрасными. Сравнивать внутри одного ключа без учёта порядка (или
  добавить в ключ `args_fingerprint`/`produced_evidence_ids` после разметки).
