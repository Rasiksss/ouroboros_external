## Вертикальное ревью

**Путь 1 — цикл через инструменты (`loop_driver=ouroboros`).** `aifa_goal` → `StandardPath._execute` → `_opener` даёт
`HandOver` → `execute_routed_goal(open_loop=…)` → `execute_production_goal` на сбое собирает `LoopSession` из
`_loop_parts` (те же `ScenarioChannel`/`GoalChannel`, что у `DynamicRun`), `open()`, `SwitchSink` → `LoopDesk.adopt`
(сохранение, переключение событий на `LoopEmitter` → `run_orchestrator.emit_to_run`) → `GoalResult(NEEDS_LOOP)` →
`ouro_view.goal` → `НУЖЕН_ЦИКЛ` + состояние. `aifa_move` → `tool_api` (привязка, роль) → `MoveTool` → `JobBoard` (240 с,
`ЖДИ job=`) → `OpenLoop.queue` → `decision_from_data` → `LoopSession.check` → `move` → `save` → `ouro_view.moved`.
`aifa_finish` → `FinishTool` (только корень — `tool_api`) → `check(last_word)` → `finish` → `publish_result` → `ПРИНЯТО`.
Границы сверены с §3.0–§3.1: коды первой строки, привязка по `run_id` из транспорта, `case_id`/`doc_ids` — из записи
хода, не из аргументов; автор кода — `atom_author.py` внутри `_move` (ADR-0029). Сквозной контрактный тест проходит
путь целиком на живом ouroboros (журнал хода, `dynamic_move`, финал корня на экране). Находка — **В1** (ниже).

**Путь 2 — старый драйвер (`loop_driver=engine`).** `DynamicRun(LoopSession).run`: `open` → `_draft_plan` → цикл
`limit()` → `_ask_planner` (модель → `parse_decision` → тот же `check`) → `reject`/`move`/`finish`, `_stop` →
`finish`/`stopped`. Сверено построчно со старым `run()`: номера ходов, счёт отказов подряд (молчание модели не
считается), сброс `rejected` при принятом решении, порядок проверки пределов, `_stop` с номером `turns + 1`,
`author_attempt.move` — эквивалентны. Единственное отличие — строка «Осталось» в подсказке последнего слова (З7).

**Отказы.** `нет_цикла` без цикла и после `ГОТОВО` (C3.9) — тест; повтор тупика — `повтор_тупика`; `ЛИМИТ` на ходу,
исчерпавшем предел, затем `ЛИМИТ` без исполнения; последнее слово без гейта файла; `файл_не_собран`; `finalize` с
несуществующей ссылкой и с проваленной проверкой — по-прежнему отказ (правила завершения не сняты, ADR-0029, 0044 п. 2);
`aifa_doc` — чужой `doc_id` → `нет_документа`, длинный документ — частями с номером следующих страниц (C3.6).
Отклонённое последнее слово закрывает цикл сводкой — но без публикации на экран (**В1**).

**Очередь (C3.8).** `asyncio.Lock` на открытый цикл внутри задания `JobBoard`: два `aifa_move` — по одному (тест по
отрезкам времени), `aifa_state` во время `aifa_move` — сразу, ожидание очереди входит в срок, `ЖДИ job=` → `aifa_wait`.
Чтение идёт мимо блокировки по живой сессии из другого потока (З4).

**Перезапуск.** `LoopDesk._restore`: `state.LOOP_SESSION` (ключ — владелец и `run_id`) → `restore_loop_session`
(контекст, рантайм, каналы — заново; накопленное — `restore_state`; атомы — из `Case`) — тест на пустом `LoopDesk`
после хода: журнал, счётчики, номер следующего хода. Время простоя процесса в бюджет цикла не входит (З6).

## Горизонтальное ревью
- **Одно место правил.** Правила §8 и столбца «Правила» держат `LoopSession.check`/`_verdict`, `_move`,
  `check_request`, `RunLimits` через `limit()`; в роуте, `ouro_view` и плагине правил нет. Реакция на исчерпание и
  `цикл_закрыт` — в `loop_tools.py` (решение ведущего, как `run()` у `DynamicRun`) — З3.
- **`parse_decision`** переиспользован: `parse_decision` → `decision_from_data`; путь инструментов зовёт ту же функцию,
  `answer_in_chat` снимает только требование `answer` (ADR-0044 п. 2).
- **`DynamicRun.run` поверх `LoopSession`** — одна реализация правил (наследование; обосновано в записи реализации).
- **Правила цикла не изменены**: `_verdict` — дословно прежний `_ask_planner`; `aifa_finish` без `answer` — `ПРИНЯТО`
  без текста; `details` финального хода — «ответ — в чате»/файлы; в `loop_rules.yaml` правила 13a/16/17 — в `deferred`.
  «Отказ тратит ход» — новое для ведущего-ouroboros, но принято ADR-0051 п. 4 (владелец).
- **Временный `loop_driver`** — поле `Settings` с «удаляется в шаге 19», R47 в §5, строка в `engine.env.example`.
- **Структурный перенос** — отдельный коммит `f6e30d8` (только `dynamic_run.py`, без новых кодов и API).
- **Снимок схем** — ADR-0051 (принята владельцем), 2823 знака; F4 зелёная. Снимок и `tool_names.json` изменены
  коммитами раньше коммита ADR (З9).
- **Безопасность**: текст документа уходит только через `aifa_doc`, документ — только из `record.doc_ids`, артефакты —
  только `Case` хода; в логах — `run_id[:8]` и число ходов, без текста.
- **Тексты пользователю** — по-русски; ответы модели содержат внутренние коды §3.0 — так задано контрактом.

## Замечания

### Важно
- **В1. Отклонённое «последнее слово» не публикует итог на экран, а ответ говорит, что файлы опубликованы.**
  `aifa/finengine/src/finengine/assistant/loop_tools.py:241-249`: при `last_word` и отказе `check` вызывается
  `session.stopped(checked)` и сразу `ouro_view.accepted(result, reason=…)`; `publish_result` (карточки `typed_result`
  частичных итогов и `file` частичных файлов) не вызывается. У ведущего-службы тот же исход (`DynamicRun._stop` →
  `stopped`) публикуется `_dynamic_outcome` (`production_runtime.py`). `ouro_view.accepted` при этом пишет «Файлы
  опубликованы: …» по `result.deliverables`. Воспроизведение: `RunLimits(max_moves=1)`, файл в `Case`, ход, затем
  `aifa_finish(finalize, evidence_ids=["no-such-id"])` → `ПРИНЯТО … Файлы опубликованы: итоги.xlsx`, событий `file` и
  `typed_result` нет. Нарушает эквивалентность ведущих (ADR-0029, ADR-0051 п. 5 «как `DynamicRun._stop`») и §3.1
  «файлы публикуются на экран».
- **В2. LR-26 «части цели по ссылке и `depends_on`» через API проверяется только наполовину.**
  `tests/loop_tools/test_loop_rules.py::test_a_part_of_the_goal_must_be_one_the_goal_has` проверяет неизвестный
  `goal_ref`; правило `depends_on` (`dynamic_run.py:730`) через API не проверено ни одним тестом (есть только у
  `DynamicRun` — `test_goal_by_reference.py::test_R18_5_…`). F8 требует тест правила через API (ADR-0044 п. 9).

### Замечания
- З1. `dynamic_run.py:1588-1596` — код отказа хода (`нет_входов`, `лимит_атомов`, …) выводится из текста отказа по
  подстроке (`_REFUSAL_MARKS`): правка формулировки молча меняет код §3.0. `Rejection(str)` с атрибутом — тоже обход типа.
- З2. `standard_path.py:73` — `assert` в коде продукта (`python -O` его снимет; нарушение инварианта — исключение).
- З3. `цикл_закрыт` и `ЛИМИТ`-гейт продублированы в `MoveTool`/`FinishTool` (`loop_tools.py:198-202`, `:229-230`), а не в
  `LoopSession`; сейчас корректно, но второе место для правила §3.0.
- З4. `aifa_state` во время `aifa_move` читает живую сессию из другого потока без блокировки (`read_tools.py:48` →
  `state_sections`: `run.atoms`, `run.journal`): возможен `RuntimeError: dictionary changed size during iteration` → 500.
- З5. `ouro_view.goal` → `_state` → `case_rows` (синхронный запрос к базе) в потоке цикла событий (`goal_tools._answer`).
- З6. `loop_state.py:307, 322` — после перезапуска время простоя в бюджет 1200 с не входит (`elapsed`), хотя ADR-0023
  считает предел «от открытия цикла».
- З7. Ведущий-служба: в подсказке «последнего слова» «Осталось ходов» теперь на 1 меньше (`turns` вместо прежнего
  `moves_used`) — малое изменение промпта на пути `engine`, который «не меняется».
- З8. `doc_matches`/`documents` (`ouro_view.py`) не держат `result_limit` (длинный `query` повторяется в ответе).
- З9. `tools.snapshot.json` (`1ea27f4`) и `tool_names.json` (`11ae7e3`) изменены коммитами раньше ADR-0051 (`84f7281`);
  F13 проверяет диф целиком и зелёна, но PRINCIPLES А.3 — «в коммите с новой ADR».
- З10. `test_loop_rules.py` — LR-03 проверяет только `ОТКАЗ` без кода; в LR-18 мёртвая переменная `unmade`.
- З11. `dynamic_run.py:730-735` — подсказка `depends_on` велит «назвать опору в goals этого же хода», но такой ход
  после тупиковой попытки отклоняется `повтор_тупика` (сигнатура «часть goal-2» не изменилась). Поведение `DynamicRun`
  до шага 13 — найдено при написании теста В2.
