# ADR-0078. Лёгкая приёмка корня: значения движка принимаются как истина

Статус: принято (владелец, 23.10.2026) для проверки на dev
Заменяет: в ADR-0070 — смысловую приёмку операндов, рядов и ссылок корнем; в ADR-0072 — приёмку
расчётных показателей после чтения входов и правило «корень читает отчёт для проверки»

## Контекст
Прогон 5fe06b06: после первого хода (17 показателей) корень ~9 минут листал индекс артефактов
(9 вызовов `aifa_state` по 20 штук), писал `step`/`review` с отказами (`stale expected_version`,
`step update must match the running attempt`) и сверял значения. Предыдущие прогоны: 9–12 минут на
ту же возню. Проверка не защитила от суженного операнда (долг по одной строке) и не окупается по
времени: цикл ограничен 40 минутами.

## Решение
Тексты навыков, код не меняется.
- `aifa-planning` 2.7.0: раздел «Корень не читает отчёт» — значения, страницы и периоды движка
  истина; `aifa_doc` до заказа плана и при приёмке не вызывается, только по прямому вопросу пользователя.
- `references/plans.md`: «Приёмка лёгкая» — шаг принимается по результату: `pass`, если вызов вернул
  нужные артефакты (список — в ответе `aifa_move`); `observation_refs` — `result_refs` из ответа
  `step`; индекс артефактов не листать; `fail` — только при отсутствии артефакта, ошибке вызова или
  файле без требуемых листов. Убраны проверки операндов, определений, рядов, прогнозов и ссылок.
- Остаются: правила автора файла (компоненты расчётных показателей, `facts`, ADR-0072), правила
  внешних рядов (`external-data.md`, ADR-0070: прогноз не факт), числа ответа только из `facts`.

## Следствия
Корень больше не ловит ошибки движка и авторов (суженный операнд, прогноз вместо факта попадут в
файл). Качество данных теперь держат извлечение, атомы и их тесты, а не приёмка корня; полноту
проверяет пользователь при чтении файла. Проверка эффекта — время приёмки в живом прогоне.
