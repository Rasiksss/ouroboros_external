# ADR-0055. Все активные LLM-роли dev используют Holy API и deepseek-v4.1-flash

Статус: принято (владелец, 21.10.2026, прямое указание в сессии шага 18)
Заменяет: ADR-0017 (выбор провайдера и моделей dev), ADR-0049, ADR-0050

## Контекст

Владелец поручил переключить dev с Cloud.ru на `https://api.holyapi.workers.dev/v1`
и во всех точках использования LLM выбрать `deepseek-v4.1-flash` вместо моделей из постановки шага.
Проверки шага 18 теперь измеряют эту модель. Секрет предоставлен отдельно и в git не хранится.

## Решение

Только в проекте `aifa-sym`: основная, лёгкая и запасная модели ouroboros, разбор запроса,
`locate`, `read.value`, временный планировщик службы и классификатор новостей используют
`deepseek-v4.1-flash` через указанный endpoint. Удалённого автора службы не восстанавливаем.

Ouroboros использует штатный адаптер `cloudru::` с переопределённым
`CLOUDRU_FOUNDATION_MODELS_BASE_URL`; префикс обозначает адаптер, фактический адрес — Holy API.
Служба использует существующие `FINENGINE_OPENROUTER_BASE_URL` и `OPENROUTER_API_KEY`.
Ключ один у обоих процессов, только в серверных env-файлах с правами 600.

## Следствия

Ядро, инструменты и пределы комнаты/цикла не меняются. Старый dev и prod не затрагиваются.
Возврат на Cloud.ru без указания владельца не делается. Резервные копии окружения остаются
на сервере вне git. Доступность `/models` сама по себе не доказывает работу генерации.

## Чем проверяется

F9 (`test_dev_config.py`): все модели и оба адреса совпадают с решением;
подмена endpoint службы обнаруживается. Живые результаты — `plan/reports/18-file-runs.md`.
