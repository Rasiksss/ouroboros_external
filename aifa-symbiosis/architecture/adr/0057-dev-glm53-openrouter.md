# ADR-0057. Живой dev использует GLM-5.3 через OpenRouter

Статус: принято (прямое указание владельца, 21.10.2026)
Заменяет: ADR-0056 в части выбранной модели

## Контекст

После двух UI-прогонов на DeepSeek-V4-Flash владелец поручил переключить
модель UI на GLM-5.3 в OpenRouter. Маршрут infproxy отвергал z-ai/glm-5.3
с HTTP 400: модели не было в allowlist. Владелец отдельно разрешил добавить
только этот идентификатор и пересоздать общий infproxy, сохранив настройки и ключи.
Это явное исключение из запрета aifa/AGENTS.md §10 для данной операции.

## Решение

Все активные роли живого aifa-sym используют z-ai/glm-5.3 через прежний
http://172.17.0.1:8820/v1. Ouroboros сохраняет существующий адаптер cloudru::.
В INFPROXY_ALLOWED_MODELS добавлен только z-ai/glm-5.3, ALT-маршрутизация
не меняется: эта модель уходит в OpenRouter, не в Cloud.ru.

## Следствия

Env-файлы aifa-sym сохранены в резервные копии before-glm53, права 600.
Настройки и снимок контейнера infproxy до изменения сохранены на сервере,
root:600. Приложения prod не пересоздавались; общий infproxy пересоздан
с разрешения владельца. Штатная сборка непреднамеренно обновила базовый Python
3.12.13 → 3.12.15; исходный образ по digest оказался недоступен для возврата.
Код app.py совпадал с прежним контейнером, ключи, сети, порты, лимиты и маршруты
сохранены. Полная идентичность зависимостей прежнему образу не подтверждена.

Примеры окружения и F9 пока не синхронизированы с живым стендом.
Создание учётки admin1 — операционная задача, без изменения auth-контрактов
и без предоставления администраторских прав по одному лишь имени пользователя.

## Чем проверяется

Прямой вызов GLM-5.3 через infproxy: HTTP 200, содержательный ответ за 2,30 с.
Оба сервиса aifa-sym healthy, фактические модели проверены через container env
без вывода ключей. Вход новой учёткой подтверждён HTTP 200 через фронтенд.
Подробности и UI-проверка — plan/reports/dev-glm53-admin1-2026-10-21.md.
