# ADR-0001. Архитектура закрепляется ADR, C4, контрактными тестами и автоматическими проверками

Статус: принято (14.10.2026, сессия архитектуры)

## Контекст
Перенос идёт много сессий подряд, разными агентами, с ограниченным контекстом. Архитектура,
которая живёт только в тексте, размывается: каждая сессия видит малый кусок и принимает
локальные решения. У ouroboros есть свой механизм (инварианты, `.rules/`, OpenSpec), у AIFA — свой
(нерушимые решения, раздел 8 плана 34 «правила держит код»). Для симбиоза нужен общий слой.

## Решение
Четыре опоры, каждая отвечает на свой вопрос:
1. **ADR** (`adr/`) — *почему так*. Решение меняется только новой записью.
2. **C4 на Mermaid** (`ARCHITECTURE.md`) — *что из чего состоит*: контекст, контейнеры, компоненты
   службы движка и используемые компоненты ouroboros; две диаграммы последовательности.
3. **Контракты** (`CONTRACTS.md`) — *как части говорят друг с другом*; у каждого контракта есть
   контрактный тест.
4. **Автоматические проверки** (`FITNESS.md`) — *что не даёт архитектуре размыться*: импорты,
   бюджет описаний, отсутствие текста документа, неизменность событий экрана, заморозка кода
   ouroboros. Дополняет их **опорная запись** поведения AIFA (этап 1) — исполняемая спецификация
   поведения.

Уровень C4 «код» не рисуем: его заменяют контрактные тесты. Structurizr и подобные инструменты не
вводим: Mermaid рендерится в GitLab/GitHub и читается агентом как текст.

## Следствия
- Изменение `ARCHITECTURE.md` или `CONTRACTS.md` без новой записи ADR — нарушение (F13).
- Сессия читает указатель ADR и только нужные записи — дешевле, чем весь документ.
- Схемы контрактов (JSON Schema) лежат в `aifa/contracts/` как данные, а не код: их читают оба
  окружения Python и фронтенд.

## Чем проверяется
F13 (дисциплина ADR); F1–F12 по существу.
