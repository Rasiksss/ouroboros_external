# ADR-0097. Dev: планировщик GLM-5.3/low, корень DeepSeek V4 Pro через OpenRouter

Статус: принято (прямое поручение владельца, 27.10.2026)

## Контекст

После повторного сравнения владелец поручил переключить планировщика на GLM-5.3/low,
корень на DeepSeek V4 Pro и запустить полный сценарий в UI. Отдельно подтверждён
провайдер OpenRouter на dev. Результаты генерации предложений не заменяют полный UI-тест.

## Решение

- Только compose-проект `aifa-sym`: корень `cloudru::deepseek/deepseek-v4-pro`,
  `distribution:aifa-plan-author=cloudru::z-ai/glm-5.3@low`.
- Оба маршрута идут через существующий Infproxy `http://172.17.0.1:8820/v1` в OpenRouter.
  Префикс `cloudru::` выбирает совместимый адаптер runtime; внешний провайдер задаётся URL.
  Общая конфигурация Infproxy не меняется. Автор атомов сохраняет прежнюю модель.
- Вместе применяются проверенные ADR-0095/0096: дедупликация подзадачи и полный контекст.
  Из-за свободного места менее 600 МБ используются тонкие слои поверх текущих dev-образов
  с явным списком изменённых исходников. Зависимости, миграции и остальные сервисы не меняются.
  Исходники доставляются git bundle; перед заменой сохраняются теги образов и копия env для отката.

## Проверка

Проверить хэши исходников в новых образах, health engine/ready Ouroboros, эффективные переменные
моделей и URL, затем новый прогон с прежним документом и запросом в UI. По событиям проверить
фактические модели корня и планировщика и переход к исполнению принятого плана.
