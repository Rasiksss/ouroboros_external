# ADR-0005. Поэтапный перенос с опорной записью; старый AIFA работает параллельно

Статус: принято (владелец, решения №4 и №25)

## Решение
Перенос идёт этапами 0–6 (`ARCHITECTURE.md` §8). На этапе 1 записывается поведение нынешнего AIFA
на наборах приёмки S0–S5, А1–А8: потоки событий экрана, тексты ответов, итоговые `Case`. Каждый
следующий этап сравнивается с записью. Старый AIFA на dev работает параллельно до прохождения
приёмки; затем путь через OpenClaw удаляется.

## Следствия
- Два источника истины на время параллельной работы — известный риск (`SYMBIOSIS.md` §7).
- Записи — данные в `aifa/tests/golden/`; сравнение — через нормализатор (без идентификаторов,
  времени, длительностей).

## Чем проверяется
F5, приёмка этапа 6.
