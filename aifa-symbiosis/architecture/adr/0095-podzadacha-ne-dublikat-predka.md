# ADR-0095. Подзадача не дубликат предка, отказ приходит итогом подзадачи

Статус: принято (прямое поручение владельца исправить найденную ошибку, 27.10.2026)

## Контекст

На dev запрос планировщика `dc2ccc95` отклонён как дубликат активного корня `3136dda1…`.
Корень получил ID до решения supervisor и продолжил `aifa_wait`. Отказ ушёл без `task_id`,
поэтому шлюз AIFA классифицировал его уведомлением и не завершил ожидание.

## Решение

- Разрешена точечная правка `supervisor/events.py` и её регрессионные тесты: явное поручение
  владельца — исключение из заморозки ядра (F1).
- В дедупликацию не передаются родитель и его предки того же владельца и агента. Чужая запись,
  отсутствующая запись и повтор ID останавливают обход. Siblings и независимые задачи остаются
  кандидатами; смысловое сравнение по-прежнему делает модель.
- Отказ дублирующей подзадаче передаётся с её `task_id`, исходным transport и существующим
  префиксом ошибки подзадачи. Подавление подтверждения приёма не подавляет отказ.
- Статус `rejected_duplicate` сохраняется; конфигурация и API не меняются.

## Проверка

`tests/supervisor/test_subtask_admission.py`: запрос с текстом предка допускается, sibling
отклоняется с коррелированным итогом, чужой владелец не влияет на исключение кандидатов.
Поведение supervisor описано в OpenSpec `reject-subtasks-with-correlated-outcome`.
