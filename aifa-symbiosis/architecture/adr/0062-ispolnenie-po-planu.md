# ADR-0062. Исполнение связано с попыткой плана, лимиты dev удвоены

Статус: принято (владелец, 22.10.2026: «проведи правки, которые будут требоваться по результатам прогонов… увеличение лимитов… хотя бы в два раза»).
Уточняет ADR-0061, ADR-0052 и dev-лимиты ADR-0058. Не меняет модель и провайдера.

UI выявил P135/P136: добровольный журнал не удерживает исполнение, отмена ждёт завершения
корня, а обрезка ответа прячет готовый результат. Приёмка файлов не пройдена.

1. Ouroboros dispatch требует явную revision/step/attempt у исполнительных вызовов корня
   с принятым планом; записывает фактический call_id и child task_id до отправки работы.
   Активное исполнение препятствует закрытию шага и плана. Значение результата принимает корень.
2. cancel_task немедленно отправляет существующее событие отмены тем же каналом AgentEvents.
   Отмена ожидания не подтверждает остановку рабочего тела: попытка остаётся активной.
   Закрытие цикла резервирует исключение новых вызовов под блокировкой корневой записи.
3. aifa_state отдаёт страницы индекса артефактов, фильтр типа и компактные значения.
   Готовые результаты ищутся по id, а не повторным запуском графа.
4. Dev: цикл40мин, подзадача20мин, граф минимум30мин, hard timeout90мин у обоих продуктов.
   Предел цикла задаётся окружением; production defaults не меняются. Служба не валидирует план.
   Предел обработчиков aifa_move/aifa_finish — 5400 с, отдельного HTTP-запроса — прежние 300 с.
   Связанный с планом вызов дожидается `ЖДИ job` через существующий aifa_wait; неопределённый
   исход опроса оставляет исполнение активным. Это продолжение вызова, а не повтор хода.
5. В навыках сдача файлового атома и создание файла — один шаг, без повторного прогона атома.
   Авторы xlsx/pptx могут работать независимо после принятых входов; аналитический текст не
   заказывается по всему реестру, если задача покрывается имеющимися проверенными показателями.
6. Каталог атомов, новые исходы исполнения и восстановление графов не входят в эту правку.

Исключения F1 — только именные пути с ADR-0062 в core_freeze_exceptions.txt.
Проверки: настоящий dispatch + runtime PostgreSQL, живая доставка отмены в event double,
пагинация артефактов и сохранение полных чтений, конфигурация dev, повтор исходного UI-сценария.
