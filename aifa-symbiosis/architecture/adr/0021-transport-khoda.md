# ADR-0021. Транспорт хода: WebSocket браузерного транспорта, `client_message_id` = `run_id`

Статус: принято (14.10.2026, сессия архитектуры)

## Контекст
Факты из `transport/browser/ws.py` и `ouroboros/agent/core.py`:
- личность решается до приёма соединения; отказ — закрытие рукопожатия;
- входящий кадр `{"type":"chat","content","client_message_id"}` сохраняется, затем приходит эхо
  (роль `user`, тот же `client_message_id`);
- исходящий ответ — кадр `chat`, роль `assistant`, `is_progress`, `task_id`, `trace_id` и
  `transport.source_message_id` = `client_message_id` входящего; прогресс — тот же кадр с
  `is_progress: true` и текстом «💬 …»;
- признака «последний ответ» нет; подзадачи наследуют `transport` корня, их сообщения и
  уведомления («🗓️ Scheduled task …», «⏱️ Task … running») тоже приходят в чат;
- исходящее доставляется только подключённым клиентам этого владельца + агента + чата; если
  клиента нет, кадр подтверждается и теряется для живой доставки (история остаётся);
- остановка — команда `{"type":"command","cmd":"/stop"}`.

## Решение
1. **Одно соединение на ход.** Служба открывает `WS /ws` с `X-Ouroboros-Owner-Id`,
   `X-Ouroboros-Chat-Id`, `X-Trace-Id` (= трасса хода) и держит его до финального ответа или
   крайнего срока хода (`OUROBOROS_HARD_TIMEOUT_SEC` + 60 с).
2. **Ключ хода — `run_id` службы.** Он уходит как `client_message_id` и возвращается в
   `transport.source_message_id` каждого кадра хода и в каждом вызове инструмента
   (`ToolContext.transport`). Отдельного ключа хода нет.
3. **Корень хода** = задача, чей `task_id` служба узнаёт из первого вызова инструмента
   (`ctx.root_task_id` пуст → это корень, `ctx.task_id`). Если инструментов не вызывали, корень —
   задача первого непрогрессного кадра ассистента с непустым `task_id`.
4. **Финальный ответ** = первый кадр `chat`, роль `assistant`, `is_progress: false`,
   `transport.source_message_id == run_id`, `task_id == корень`. Кадры подзадач, уведомления без
   `task_id`, прогресс — в журнал хода как служебные, на экран не идут (строка «размышляю» снята).
5. **Восстановление.** Если соединение порвалось или служба перезапустилась, служба читает
   `GET /api/chat/history` чата и ищет запись ассистента с `client_message_id == run_id` корневой
   задачи; не нашла до крайнего срока — ход закрывается событием `session_lost`, как сейчас.
6. **Отмена** кнопкой «Стоп» = команда `/stop` в соединение хода + отмена фоновых заданий службы
   этого хода.

## Следствия
- Пункты 3–4 опираются на поведение, которое надо подтвердить живым контрактным тестом на этапе 2
  (C2.3–C2.5): что финальный кадр корня несёт `task_id`, а уведомления о подзадачах — нет.
- Посимвольной выдачи нет — уже принято (ADR-0015).

## Чем проверяется
C2.
