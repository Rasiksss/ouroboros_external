# ADR-0080. Недостача извлечения возвращается планировщику

Статус: принято (владелец, 23.10.2026) для проверки на dev

## Контекст
Прогон 3f05f49d: движок три раза ответил «BANK_DEPOSITS не найден» (показатель есть в
«Рассчитываемых» и «Извлекаемых»), а корень искал обходы: ad-hoc формулы, новые атомы, повторные ходы.
Подсказки толкали его к этому: отказ службы («новый атом либо give_up», «ту же ссылку не повторяй») и
`moves.md` («следующим ходом рассчитай его; не ищи шагами `locate`/`read.value`»). Замысел другой:
корень исполняет план, при недостаче возвращается к планировщику, тот переделывает шаг.

## Решение
Только тексты навыков и сообщение службы, ядро не затрагивается.
- `aifa-plan-author` 1.6.0, раздел «Пересмотр при недостаче»: переделать только шаг с недостачей
  (id остальных сохранить); рассчитываемый показатель — шаг расчёта через компоненты; строго
  извлекаемый — внешний поиск (`web.search`, загрузка) и расчёт по найденному; эквивалента нет —
  допущение и вопрос, без подмены близким показателем; тот же шаг теми же аргументами не повторять.
- `plans.md`, «Недостача»: второй такой же вызов не делать, обходов не изобретать; шаг `failed` с
  причиной и подзадача пересмотра с шагом, показателем, ответом движка, числом попыток, ревизией.
- `moves.md`: один раз расчёт сценарием, дальше пересмотр плана.
- Служба (`dynamic_run.py`, агентский вход): отказ части цели называет возврат планировщику, а не
  «новый атом либо give_up». Путь собственного планировщика службы не меняется.

## Проверка
`tests/loop_tools/test_agent_goals.py` (отказ части называет пересмотр плана), три теста текста навыков
(`test_calculated_values_and_final_text.py`); живой прогон: ведёт ли недостача к новой ревизии плана.
