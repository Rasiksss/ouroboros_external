# ADR-0093. Автору — id артефактов, а не значения; в ходе только независимые действия (тексты навыков)

Статус: принято (владелец, 27.10.2026) для проверки на dev; сопровождает ADR-0092

## Контекст
Прогон 27.10 (ed53d54a): перед заданием автору Excel корень пятнадцатью вызовами читал артефакты (08:13–08:19, шесть минут),
чтобы вписать в задание значения и страницы, и сам посчитал среднегодовые ставки по таблице страницы (08:13); цикл исчерпан
на 44-й минуте, Excel не собран. Автору достаточно id: артефакты он читает сам через `aifa_state`. `SKILL.md` просил в
задании «id артефактов», а `artifacts.md` — «каждое число в задании подзадаче из таблицы артефактов»: второе подталкивало
переписывать значения. После ADR-0092 текст про «части выполняются до шагов хода» стал неверным.

## Решение
- `aifa-planning` 2.15.0: `SKILL.md` (задание подзадаче) — входы только id артефактов, без значений, читает подзадача;
  `references/artifacts.md` — в задании id, а не значения и страницы; число, которого нет ни в одном артефакте (среднее по
  таблице страницы), корень не считает и не вписывает: называет автору id страницы и что посчитать;
  `references/moves.md` — части цели и шаги атомов одного хода исполняются одновременно, зависимое — в следующий ход;
  `references/plans.md` — все действия шага служба исполняет одновременно.
- `aifa-plan-author` 1.15.0: действие, которому нужен адрес, значение или файл из результата другого действия, — следующий
  ход; действия одного хода результата друг друга не увидят.
- Размер `SKILL.md` — в пределах 9000 знаков: новое правило помещено заменой фразы, подробности — в справочнике.

Не затронуто: схема и договор `task_plan`, служба (ADR-0092).

## Проверка
`skills/aifa-engine/tests/test_planning_speed_text.py`: два теста красные до правки (id автору и ставки не считает корень;
действия хода одновременно, зависимое — в следующий ход), тест размера руководства остаётся зелёным. Живой прогон: задание
автору содержит id и не содержит значений; корень не листает артефакты перед заданием.
