# ADR-0086. Формулы реестра не меняются и не заменяются ad-hoc формулой

Статус: принято (владелец, 26.10.2026) для проверки на dev; усиливает ADR-0082 и ADR-0083

## Контекст
Прогон 26.10 (корень 9f45ce36): BANK_DEPOSITS не найден, корень вместо способа по статусу показателей собрал чистый
долг через `calculate_ad_hoc_metric` со своей формулой (кредиты + аренда − деньги), «компонент опущен». Значения
разошлись с отчётом (−1 162 449 / −286 704 против −1 046 258 / −225 803), недостача осталась незакрытой. Запрет
обходов был, но общей фразой («ad-hoc формул не изобретай») и только в разделе о недостаче.

## Решение
Только тексты навыков; жёсткое правило вынесено в отдельный раздел и дублируется там, где формулу могут написать.
- `artifacts.md`, новый раздел «Формулы реестра не меняются»: показатель из «Рассчитываемых» считается только по
  формуле реестра, компоненты, знаки и состав не меняются; `calculate_ad_hoc_metric` — только для показателя вне
  реестра, под другим названием та же формула тоже реестровая; расчёт без компонента, даже с пометкой «компонент
  опущен», принимать нельзя; автору атома формулу реестра называют дословно.
- `moves.md`: для показателя реестра ad-hoc и свою формулу не применять.
- `aifa-plan-author` 1.11.0: план называет показатель, формулу берёт служба.
- `aifa-atom-author`: формулу показателя реестра не упрощать, компонент без значения не опускать и не заменять нулём.

## Проверка
Тесты текстов: `test_calculated_values_and_final_text.py` (четыре красных до правки). Живой прогон: недостача
BANK_DEPOSITS не уходит в ad-hoc формулу, шаг переделывается по статусу (расчёт реестра, затем интернет, затем
`partial`). Если корень обойдёт и это, нужна проверка в службе: отказ ad-hoc для показателя, чьё название или
синоним есть в реестре; решает владелец.
