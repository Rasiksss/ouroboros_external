# ADR-0094. Термины плана: план — ходы, ход — шаги; интернет для показателя отчётности — по разрешению пользователя

Статус: принято (владелец, 27.10.2026) для проверки на dev; уточняет ADR-0088, ADR-0089, ADR-0091, ADR-0092; меняет порядок поиска недостающего показателя в ADR-0082
Заменяет: терминологию «шаг плана = ход» (ADR-0089, ADR-0091); автоматический поиск в интернете недостающих значений показателя отчётности (`artifacts.md`, ADR-0082)

## Контекст
Аудит инструкций 27.10 (`plan/reports/instruction-audit-27-10.md`): слово «ход» означало прогон, вызов `aifa_move` и шаг плана,
слово «шаг» — запись `task_plan` и вызов атома. Прогон 65ce9c83: планировщик не слил независимые шаги в один, корень не вернул
план, ходы шли подряд. Отдельно: при «НЕ РАССЧИТАН» навык требовал искать недостающие значения показателя компании в
интернете сам, что противоречит «показатели компании — только из отчёта» и просьбе пользователя «не додумывай».

## Решение
1. Три термина во всех инструкциях AIFA (`aifa-planning`, `aifa-plan-author`, `aifa-atom-author`, `aifa-engine`):
   **план** — набор ходов; **ход** — набор шагов; **шаг** — действие с конкретным результатом (вызов атома, часть цели со
   сценарием службы, заказ подзадачи). **Прогон** — вся работа над сообщением пользователя. В схеме `task_plan` ход называется
   `step` (`step_id`, `accept_step`): имена схемы не меняются (ядро ouroboros, F1), навыки это оговаривают.
2. Навык планировщика: блок «ВАЖНО. Устройство плана» — план есть цепочка последовательно зависящих ходов (ход 2 использует
   результат хода 1, ход 3 — хода 2; параллельно ходы выполнить нельзя); ход — исключительно независимые шаги, они выполняются
   параллельно; пример на три хода. Шаги-авторы одного уровня — шаги одного хода (одна попытка, несколько вызовов).
3. Навык корня: план принимается по двум критериям — покрытие целей пользователя и оформление (каждый ход после первого
   использует результат предыдущего; в ходе нет шагов, зависящих друг от друга; независимые шаги не разнесены по ходам).
   Ошибка оформления возвращается планировщику один раз, как и ложная зависимость по ADR-0091.
4. Часть цели, которой нужен результат другой части, идёт в следующий ход; `depends_on` называет опору, полученную ранее.
   Пример `scenarios.md` разнесён на два хода. Служба по-прежнему умеет слои `depends_on` внутри хода (ADR-0088), инструкции
   этим не пользуются.
5. Показатель отчётности, не найденный в отчёте, агент в интернете по своей инициативе не ищет и интернетом не подменяет.
   Он закрывает цикл `aifa_finish(finalize)` по имеющемуся и спрашивает пользователя: «Показатель X в отчёте не найден; могу
   попробовать найти его в интернете — искать?». Только с разрешением (в сообщении или раньше в разговоре) — `web.search`,
   загрузка, расчёт. Планировщик не планирует внешний поиск такого показателя без разрешения: допущение и вопрос в `questions`.
   Внешние ряды (ставки, курсы, цены, новости) этим правилом не затронуты.

## Следствия
- Тексты инструментов и службы (`plugin.py`, `ouro_view.py`, коды `чужой_ход`, «документ хода») не менялись: снимки схем и F-проверки
  остаются; в навыке «ход» в кодах инструментов оговорён как прогон. `dynamic_run_planner.md` (модель самой службы) не менялся.
- `SKILL.md` aifa-planning в пределе: 8978 из 9000 знаков; подробности оформления — в `references/plans.md`.
- Не затронуты (остаются открытыми по аудиту): чистый долг при «возьми из отчёта», число попыток переделки, порядок закрытия
  `aifa_finish` и `task_plan.finish`, остальные пункты `instruction-fixes-27-10.md`.
- Неизвестно до прогона: переносит ли модель шаги-авторов одного хода под одну попытку `task_plan` (контракт это допускает).

## Чем проверяется
`skills/aifa-engine/tests/test_plan_terms.py` (пять тестов красные до правки), переписанные тесты `test_planning_speed_text.py` и
`test_calculated_values_and_final_text.py` под новые формулировки; `test_the_guide_stays_within_its_size_limit`. Живой прогон:
план из ходов-цепочки, независимые шаги в одном ходе, при ненайденном показателе — вопрос пользователю вместо поиска.
