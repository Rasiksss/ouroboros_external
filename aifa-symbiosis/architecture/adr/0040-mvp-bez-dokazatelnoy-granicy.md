# ADR-0040. MVP: числа не обязаны идти из доказательной базы; ouroboros видит документ и артефакты

Статус: принято (владелец, 16.10.2026; риск принят владельцем на время MVP); п. 3 (подцель в `aifa_goal`) заменён ADR-0042
Заменяет: ADR-0025; ADR-0004 — в части гарантии и «цель только из исходного сообщения»;
ADR-0024 — в части канонического текста

## Контекст
- Две гарантии держали архитектуру цикла: «числа только из доказательной базы» (ADR-0004,
  проверки `aifa_finish`) и «ouroboros не видит текста документа» (ADR-0025, `ouro_view`, F3, F6).
  Из-за них служба сама выдавала задания подзадачам, готовила автору сокращённый вход и сверяла
  финальный текст с каноническим (ADR-0008, ADR-0024). Каждый новый навык ouroboros требовал бы
  новой ветки логики в службе.
- Владелец решил на время MVP снять обе гарантии и после сборки MVP по итогам тестирования решить,
  возвращать ли контроль. Это расходится с нерушимым решением AIFA №3
  (`aifa/finengine/docs/build-plan/01-nerushimye-resheniya.md`): на время MVP оно отложено.
- Нерушимое решение №9 (код, запущенный моделью, — только в песочнице без сети по умолчанию) не
  меняется: атомы графа исполняются в разовой комнате (ADR-0007).

## Решение
1. **Числа.** Ответ модели не обязан ссылаться на доказательства. `aifa_finish` не требует
   ссылок; переданные ссылки служба не отвергает, а записывает в журнал прогона, существует ли
   каждая (замер для решения после MVP).
2. **Текст документа и артефакты.** Ouroboros может получать распознанный текст документов хода
   (по страницам и поиском) и полное содержимое артефактов `Case`. Отдаются только инструментами
   `aifa-engine` (ADR-0042); вложения в кадрах WS по-прежнему не передаются, инструменты чтения
   файлов ouroboros остаются выключенными (ADR-0027): так документ приходит один раз и в уже
   распознанном виде, а не вторым распознаванием в ouroboros.
3. **Цель.** `aifa_goal` без аргумента берёт исходное сообщение прогона (как раньше);
   с аргументом `goal` — разбирает переданную подцель тем же путём (intent → граф).
4. **Финальный текст** — последнее сообщение корня (ADR-0024, п. 1, в силе); канонического текста
   и сверки нет.
5. **Что остаётся:** стандартный путь первым (`нет_цикла` до `aifa_goal`), `RunLimits`, повтор
   тупика, обещанные файлы, разовая комната для кода атомов, привязка вызова к ходу и владельцу,
   единый формирователь ответов `ouro_view` (грамматика C3.2, предел ответа), события экрана.

## Следствия
- Модель может выдумать или исказить число; документы целиком уходят к модели ouroboros
  (Cloud.ru); длинные документы читаются по страницам, иначе съедают контекст.
- Условие возврата: итог тестирования MVP. Возврат — новая ADR; замер из п. 1 показывает, какая
  доля ответов опиралась на `Case`.
- Проверка F3 снимается; F6 остаётся с основанием п. 2 этой записи; из карты правил F8 уходят
  правила о ссылках и опровергнутых находках.
- Задания подзадачам служба больше не выдаёт — ADR-0041.

## Чем проверяется
C3 (`aifa_finish` без ссылок — `ПРИНЯТО`; несуществующая ссылка — `ПРИНЯТО` и запись в журнале
прогона; `aifa_doc` отдаёт страницы только документов хода), F6.
