# ADR-0091. Планировщик строит план уровнями зависимости по данным, корень проверяет уровни

Статус: принято (владелец, 26.10.2026) для проверки на dev; усиливает ADR-0089

## Контекст
Прогон 26.10 (e296e677): ADR-0089 («шаг плана равен ходу») планировщик выполнил наполовину. Поиск ставки ЦБ (S2)
он записал с `depends_on: [S1]` и входом `step S1`, хотя ему нужны только годы отчёта, а они известны из `aifa_state` до
извлечения. Вместо одного хода «выкачка + поиск» получились два последовательных, а вместе с авторами — цепочка
S1 → S2 → S3 → S4. Частное правило («внешний ряд не зависит от извлечения») закрыло бы только этот случай. Причина
общая: нет определения зависимости и нет проверки плана на ложные зависимости.

## Решение
- `aifa-plan-author` 1.14.0: зависимость только по данным — шаг B зависит от A, если использует значение, файл или адрес,
  которые производит A. Для каждой пары шагов вопрос «могу ли я начать B, не дожидаясь A?»; порядок «по смыслу» и общая
  тема зависимостью не являются; известное заранее (годы, профиль, реестр) берётся из `aifa_state`. Планировщик строит
  уровни (1 без зависимостей, иначе 1 + наибольший уровень зависимостей): шаги извлечения, расчёта и поиска одного уровня —
  один шаг-ход, кодовые подзадачи одного уровня — отдельные шаги, запускаются параллельно. Уровни записываются
  допущением с id `levels` (схема `task_plan` не меняется).
- `aifa-planning` 2.14.0, `references/plans.md`: при приёмке корень проверяет уровни — для каждого `depends_on`
  использует ли шаг результат предшественника или идёт после него «по порядку». Два независимых шага извлечения,
  расчёта или поиска в разных шагах плана — ошибка плана: корень возвращает план планировщику один раз с замечанием
  (что слить, у кого убрать `depends_on`); по тому же замечанию второй раз не возвращает.

Цена возврата — новая подзадача планировщика (~2–3 минуты), поэтому он один на замечание: приёмка не превращается в
цикл переделок. Основная ставка — на планировщика; проверка корня — страховка.

Не затронуто: схема и договор `task_plan`, служба, `task_plan.accept`.

## Проверка
`skills/aifa-engine/tests/test_planning_speed_text.py`: тесты текстов планировщика (определение зависимости, вопрос про
пару шагов, уровни, допущение `levels`) и корня (проверка уровней, один возврат) — красные до правки. Живой прогон: у плана
независимые поиск и извлечение в одном шаге, допущение `levels` присутствует; если планировщик снова их разнёс, корень
возвращает план один раз.
