# ADR-0067. Dev: DeepSeek через Cloud.ru с запасным Holy API

Статус: принято для dev-эксперимента (22.10.2026, владелец разрешил подбор моделей и провайдеров)
Уточняет: ADR-0058, ADR-0065 в части живого окружения; примеры окружения не меняются

## Контекст
Прогон через UI с GLM-5.3/Holy снова читает отчёт до заказа плана; запросы также
обрываются с 524 и 502. Основная и запасная модель одинаковы, реального переключения нет.
OpenRouter возвращает 403 Key limit exceeded. Короткая проверка DeepSeek-V4-Pro напрямую
в Cloud.ru завершилась за 9,25 с. Проверки вызова инструмента прошли у DeepSeek обоих каналов.
Короткие проверки не доказывают качество полного файлового сценария.

## Решение
Проверить живой dev на `cloudru::deepseek-ai/DeepSeek-V4-Pro` для корня и лёгкой роли.
Запасная модель — `selfhosted::deepseek-v4.1-flash` с существующим совместимым адаптером,
его `OPENAI_COMPATIBLE_BASE_URL` указывает на Holy API. Cloud.ru и Holy имеют разные ключи
и адреса; настройки TLS не ослабляются. Служба использует DeepSeek-V4-Pro через Cloud.ru.
Меняются только серверные файлы окружения с резервной копией и правами 600.
Пределы времени, размер ответа и уровень размышлений не меняются. `infproxy` не меняется.
Окончательный выбор определяется повторными UI-прогонами и проверкой полученного Excel.

## Следствия
Сбой одного канала допускает переход на другой существующим механизмом fallback.
Возможности GLM-5.3 не объявляются непригодными вообще: вывод относится к этому сценарию.

## Чем проверяется
Доступность моделей, фактические адреса и имена без вывода ключей, дымовой запрос;
затем полный UI-сценарий и инспекция формул, источников, периодов и пропусков Excel.
