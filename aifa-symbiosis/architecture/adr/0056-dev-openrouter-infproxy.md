# ADR-0056. Dev использует OpenRouter через существующий infproxy

Статус: маршрут принят владельцем (21.10.2026); модель заменена ADR-0057
Заменяет: ADR-0055 в части живой конфигурации dev

## Контекст

Владелец поручил подключить OpenRouter через infproxy к aifa-sym и выполнить пару
стандартных кейсов через UI с отчётами. Предыдущие прогоны Holy API блокировались
ошибками провайдера. Владелец отдельно разрешил чтение необходимых настроек общего
deployment env и перенос клиентского токена в окружение aifa-sym без вывода секретов.

## Решение

Только живое окружение aifa-sym направляется в http://172.17.0.1:8820/v1.
Существующий infproxy, его конфигурация и prod не изменяются.
Все активные роли используют deepseek/deepseek-v4-flash: разрешённую модель
OpenRouter, ближайшую по названию к прежнему Flash. Это выбор исполнителя для
данного прогона, который владелец может пересмотреть.

Ouroboros сохраняет штатный адаптер cloudru:: с переопределённым endpoint;
служба использует FINENGINE_OPENROUTER_BASE_URL и OPENROUTER_API_KEY.
Клиентский токен копируется на сервере в env-файлы с правами 600.
До изменения сохраняются резервные копии обоих env-файлов.

## Следствия

Идентификатор deepseek-ai/DeepSeek-V4-Pro не подходит для проверки OpenRouter:
в текущем прокси он включён в INFPROXY_ALT_MODELS и направляется в Cloud.ru.
Примеры окружения и F9 ещё фиксируют ADR-0055; данная операционная задача
меняет живой стенд, синхронизация примеров и их тестовых ожиданий остаётся отдельной работой.

## Чем проверяется

До переключения: chat/completions через infproxy вернул HTTP 200 за 2,47 с,
model=deepseek/deepseek-v4-flash, содержательный ответ. После переключения:
здоровье двух сервисов, фактические настройки без секретов и UI-прогоны;
результаты — plan/reports/dev-openrouter-ui-2026-10-21.md.
