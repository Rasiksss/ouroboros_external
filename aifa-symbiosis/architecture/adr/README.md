# Записи архитектурных решений (ADR) симбиоза AIFA и ouroboros

Правило: **архитектура меняется только новой записью.** Принятую запись не правят по существу;
чтобы изменить решение, пишут новую запись со ссылкой «заменяет ADR-NNNN», а у старой меняют
только строку статуса на «заменено ADR-MMMM». Опечатки и ссылки править можно.

Источник решений 0002–0018 — раздел 4 `SYMBIOSIS.md` (решения владельца 13–14.10.2026).
Записи 0019–0029 приняты в сессии низкоуровневой архитектуры 14.10.2026; 0024–0026 — ответы
владельца на вопросы этой сессии. 0030 — фактическая git-база репозитория (14.10.2026); 0031 — ответ владельца на О1.
0032 — ответ владельца на P8; 0033 — решение владельца исключить пользовательское тестирование (15.10.2026).
0040–0042 — решение владельца ослабить гарантии на время MVP и отдать выбор навыков планировщику (16.10.2026);
0043 — исправления по ревью этих записей (`plan/reviews/05a-arch.md`); 0044 — по повторному ревью (`05a-arch-r2.md`); 0045 — решение владельца 18.10.2026: опорной записи нет; 0046 — решение владельца 18.10.2026 по итогам шага 08 (подзадача стартует после родителя); 0047 — первый снимок схем инструментов, срок инструмента в службе, допуск навыков (шаг 10); 0051 — снимок схем шага 13 и исполнение инструментов цикла; 0052 — запрос подзадачи уходит supervisor'у сразу (правка ядра, шаг 16); 0053 — снимок схем шага 16 и уточнения инструментов подзадач; 0054 — автор атомов с кодом становится навыком подзадачи, автор службы удаляется (шаг 17).

## Шаблон

```markdown
# ADR-NNNN. Название

Статус: предложено | принято (дата, кто) | заменено ADR-MMMM
Заменяет: — | ADR-KKKK

## Контекст
Что вынуждает решать; факты с путями к коду.

## Решение
Одно решение, проверяемое.

## Следствия
Что становится проще, что сложнее, какие ограничения появляются.

## Чем проверяется
Автоматическая проверка (FITNESS.md, Fnn) или контрактный тест (CONTRACTS.md, Cn).
```
