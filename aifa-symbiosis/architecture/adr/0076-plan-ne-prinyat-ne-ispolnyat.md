# ADR-0076. Непринятый план не исполняют: валидный JSON от планировщика

Статус: принято для проверки на dev (23.10.2026)

## Контекст
Прогон 2224a974 (после ADR-0075): корень не читал отчёт и сделал всего 5 записей `task_plan`, но не
потому, что стало лучше. Автор плана вернул JSON с неэкранированными `"` внутри цитаты запроса
(«…соотношение "чистый долг / EBITDA" по годам»), `task_plan(accept)` дважды ответил `Invalid JSON`,
и корень перешёл к исполнению без принятого плана. Колонка «План» осталась пустой: служба шлёт
`root_plan` только для разбираемого JSON. Прогон закончился файлом за 42 мин 34 с, но данные по чистому
долгу не сверены с отчётом (долгосрочный долг взят одной строкой примечания, ставка 2025 — из
прогнозного документа ЦБ).

## Решение
Тексты навыков, код не меняется.
- `aifa-plan-author` 1.4.0: в строках JSON нет неэкранированных `"`; цитата запроса с кавычками
  пишется в «ёлочках» или как `\"`.
- `references/plans.md`: `accept` вернул `ERROR` про форму — предложение не принято, плана нет;
  корень заказывает новую подзадачу планировщика с текстом ошибки и не исполняет без принятого плана.

## Следствия и проверка
Парсер JSON в `task_plan` не смягчается: починка кавычек эвристикой исказила бы цитаты и допустила
бы невалидные планы. Тесты текста: `test_calculated_values_and_final_text.py`. Эффект проверяет живой
прогон: принят ли план с первой попытки и виден ли он в колонке «План».
