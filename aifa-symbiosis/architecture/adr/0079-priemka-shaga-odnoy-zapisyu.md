# ADR-0079. Приёмка шага одной записью `accept_step`; критерий на шаг один

Статус: принято (владелец, 23.10.2026) для проверки на dev; правка ядра ouroboros по F1
Дополняет: ADR-0062 (исполнение по плану), ADR-0078 (лёгкая приёмка)

## Контекст
Прогон 5fe06b06: приёмка одного шага заняла ~15 из 29 минут цикла. По журналу: два вызова
`step`/`review` вместо одной записи, отказы формата (`verdict`, `decision`, «review must cover every
acceptance criterion», «failed or inconclusive criteria cannot be accepted»), ручной перенос хешей
результатов и `stale expected_version`. Каждая запись — минута размышлений корня. После лёгкой
приёмки (ADR-0078) осталась механика, которую корню выполнять незачем.

## Решение
- Новое действие `task_plan(action="accept_step", data={expected_version, step_id[, attempt_id,
  explanation]})` (`ouroboros/contracts/task_plan.py`: `AcceptStep`, `PlanState.accept_step`;
  `ouroboros/tools/service/task_planning.py`). Одна запись: берёт результаты вызовов бегущей
  попытки (квитанции `aifa_move`, итог подзадачи, как в `step awaiting_review`), записывает
  `awaiting_review`, затем `review` с `pass` на **каждый** критерий шага, `observation_refs` =
  результаты, `decision=accept`. Отказ: вызов попытки упал, возвращённого результата нет, подзадача ещё
  идёт (проверка `executor child … active`), версия устарела, шаг уже принят.
- `step` и `review` остаются для отклонения (`failed`/`blocked`, `revise`) и для шага без
  исполнительного вызова. Схема `accept_step` отдаётся в `task_plan(action="schema")`.
- `aifa-plan-author` 1.5.0: критерий на шаг один (второй — для файла со структурой); число шагов не
  ограничено. `plans.md`: после результата корень вызывает `accept_step`.

## Следствия
Корень не может принять шаг, которого не было, но и не сверяет его содержание: смысловая
проверка — ответственность исполнителя (ADR-0078). Число критериев перестаёт влиять на объём
приёмки, но влияет на то, что проверит человек при чтении плана. Старые прогоны и записи не
затрагиваются.

## Проверка
`tests/ouroboros/tools/test_plan_dispatch.py`: принятие по возвращённому результату одной записью
(+1 версия, все критерии, ссылки), отказ при упавшем вызове и без результата, ожидание бегущей
подзадачи и защита от устаревшей версии. Текст навыков — `skills/aifa-engine/tests`. Живой прогон:
время приёмки шага.
